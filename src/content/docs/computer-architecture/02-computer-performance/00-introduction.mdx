## Introduction

After designing synchronous logic and finite-state controllers in Part I, a computer architect needs a rigorous ruler to judge whether one processor or hardware optimization is actually faster than another. Marketing sheets routinely highlight isolated numbers—higher gigahertz clock rates, wider instruction issue widths, or raw "millions of instructions per second" ($\text{MIPS}$)—yet each of those metrics can improve while a real program takes *longer* to finish.

Part II establishes **elapsed CPU execution time** ($T_{\text{exec}}$) as the sole ground-truth measure of processor performance. First, the **CPU Performance Equation** decomposes runtime into three coupled quantities—dynamic instruction count ($\text{IC}$), average clock cycles per instruction ($\text{CPI}$), and clock cycle period ($T_{\text{clk}} = 1/f_{\text{clk}}$)—linking compiler output, pipeline microarchitecture, and silicon timing in one product. Second, **Amdahl's Law** bounds how much overall speedup ($S_{\text{tot}}$) any targeted hardware accelerator or multi-core upgrade can deliver when only a fraction $F$ of baseline execution time benefits from the change.

### Practical Engineering Perspective

- **Hard Real-Time Control Loops:** An embedded flight controller running a $1\text{ kHz}$ attitude-estimation filter must finish every iteration in under $1.0\text{ ms}$. Decomposing $T_{\text{exec}}$ tells firmware engineers the exact dynamic instruction budget available before cache stalls or branch penalties cause a deadline overrun.
- **Compiler and Microarchitecture Co-Design:** Aggressive compiler optimizations (`-O2`, `-O3`) eliminate fast single-cycle arithmetic instructions, shrinking $\text{IC}$ and cutting wall-clock runtime even when the surviving memory-heavy mix exhibits a *higher* average $\text{CPI}$.
- **Hardware Accelerator Budgeting:** Offloading matrix or vision kernels onto a SIMD unit, GPU, or edge NPU pays off only in proportion to the baseline runtime fraction $F$. Amdahl's asymptotic ceiling $S_{\max} = \frac{1}{1 - F}$ prevents engineering teams from over-investing silicon area on bottlenecks bounded by serial I/O.

### Running Example

Across Chapters 6 and 7, we revisit a single running benchmark: a real-time **RV32IM control iteration** executing $\text{IC} = 10^6$ dynamic instructions per $1.0\text{ ms}$ frame across arithmetic, load, store, and branch operations. In Chapter 6, we evaluate competing processor cores on this instruction mix to compute weighted $\text{CPI}$ and exact execution time $T_{\text{exec}}$. In Chapter 7, we profile the dominant matrix-filtering phase ($F = 0.75$ of runtime) against serial sensor I/O ($1 - F = 0.25$) to quantify vector-coprocessor speedup and inverse design targets.
