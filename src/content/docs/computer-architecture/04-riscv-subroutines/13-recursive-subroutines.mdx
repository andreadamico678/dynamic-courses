## Recursive Subroutines

To a RISC-V processor, recursion is not a special hardware mode—it is an ordinary `call` (`jal ra, label`) whose jump target happens to be the function's own entry label. Because every recursive invocation calls a subroutine, every recursive function is a **non-leaf function** ([Subroutine Stack Frames](/dynamic-courses/computer-architecture/04-riscv-subroutines/12-subroutine-stack-frames/)): each activation must allocate its own word-aligned stack frame to preserve **`ra`** and any live arguments or partial results needed after the recursive `jal` returns.

<Divider label="1 · Example" />

### Tracing Recursive Factorial

Let us translate and trace the recursive `fact(n)` helper from our Part IV running program for $n = 3$:

```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

When `fact(3)` runs, `a0` arrives holding `3`. Before calling `fact(2)`, `fact(3)` must overwrite `a0` with `2`, and when `fact(2)` finishes, `a0` arrives back holding the child result `2`—not the original `3`! We therefore allocate a **16-byte** stack frame in every activation, saving **`ra`** at `12(sp)` and the current parameter **`n`** (`a0`) at `8(sp)`:

```asm
# Arguments: a0 = n
# Returns:   a0 = n!
fact:
    # --- 1. PROLOGUE: 16-byte aligned activation frame ---
    addi sp, sp, -16
    sw   ra, 12(sp)          # Save caller's return address
    sw   a0, 8(sp)           # Save current n before child call overwrites a0

    # --- 2. BASE CASE: if (n <= 1) return 1 ---
    li   t0, 1
    bgt  a0, t0, fact_rec    # If n > 1, descend into recursive step
    li   a0, 1               # Base case return value = 1
    j    fact_epilogue       # Jump to shared epilogue to release our 16-byte frame

    # --- 3. RECURSIVE STEP: n * fact(n - 1) ---
fact_rec:
    addi a0, a0, -1          # Child argument: a0 = n - 1
    call fact                # Recursive jal! Returns with a0 = fact(n - 1)

    lw   t1, 8(sp)           # Reload THIS activation's saved n from 8(sp)
    mul  a0, t1, a0          # a0 = n * fact(n - 1)

    # --- 4. EPILOGUE: Restore ra, pop 16-byte frame, return ---
fact_epilogue:
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

As shown in [the figure](#fig-recursive-stack), calling `fact(3)` pushes three distinct 16-byte activation records onto the stack during **recursive descent** (`sp - 16` holding $n = 3$, `sp - 32` holding $n = 2$, and `sp - 48` holding $n = 1$). At $n = 1$, the branch `bgt a0, t0, fact_rec` is not taken: `a0` becomes `1`, frame $n = 1$ pops (`sp + 16`), and execution unwinds in strict **Last-In, First-Out (LIFO)** order—reloading $n = 2$ to compute $2 \times 1 = 2$, then reloading $n = 3$ to compute $3 \times 2 = 6$, and finally restoring `main`'s original `ra`.

<Divider label="2 · Theory" />

Every recursive C-to-RISC-V translation enforces two hardware invariants at each activation level (note that recursion is an **insurance topic**—`0/7` 2026 exams used recursion, as exam Question 6 favors iterative helpers, so mastering single-call recursion below is sufficient):

### Recursive Frame Invariants

1. **Unconditional `ra` Preservation:** Even though the deepest base-case activation executes no further `call`, every outer activation executes `call self` (`jal ra, self`), which overwrites `ra` with the instruction address immediately after `call self` *inside the recursive function*. If a recursive routine omits `sw ra` and `lw ra`, the base case returns once to `call self + 4`, and that level's `ret` jumps right back to `call self + 4` forever.
2. **Shielding Live Values:** Register `a0` plays three conflicting roles across `jal`: it brings in parameter $n$, must be overwritten with the child argument (such as $n - 1$), and returns holding $f(n - 1)$. Any value from before `call self` that appears in an expression *after* `call self` returns must be saved in the current frame using either of two equivalent idioms:
   - **Caller-Slot Idiom** (`sw a0, 8(sp)`): Spill `a0` directly to a dedicated word slot in the prologue and reload it into a temporary (`lw t1, 8(sp)`) right after `call self`.
   - **Callee-Saved Idiom** (`sw s0, 8(sp)`): Save caller's `s0` in the prologue, copy `mv s0, a0`, compute child argument `addi a0, s0, -1`, and after `call self` combine `mul a0, s0, a0` before restoring `lw s0, 8(sp)` in the epilogue.

### Base Case Teardown

Always route every return path—both base case(s) and recursive step(s)—through a **single shared epilogue label** (`func_epilogue:`). Once `addi sp, sp, -K` executes at the top of the function, jumping to `ret` directly from the base case without executing `addi sp, sp, K` leaves `sp` shifted, corrupting the caller's stack pointer and reloading the wrong `ra`. Routing `j func_epilogue` guarantees symmetric `+K` deallocation on every exit path.

<Divider label="3 · Summary" />

### Recursion Pattern Reference

| Recursion Pattern | Live Values Across `call` | Saved Slots Needed | Post-Call Recombination |
| :--- | :--- | :--- | :--- |
| **Single Linear (`fact(n)`)** | Parameter `n` | `ra` + `a0` (or `s0`) | `lw t1, 8(sp)` $\to$ `mul a0, t1, a0` |
| **Two-Arg Linear (`power(b, e)`)** | Parameter `b` (`a0`) | `ra` + `a0` (or `s0`) | `lw t0, 8(sp)` $\to$ `mul a0, t0, a0` |
| **Array Linear (`sum(arr, n)`)** | Element `arr[n-1]` | `ra` + `s0` | `add a0, s0, a0` |

### Recursive Translation Procedure

1. **Identify Live Post-Call Values:** Circle every variable in the C `return` expression that is used *after* the recursive call returns.
2. **Allocate Frame:** Subtract $K$ (word- or 16-byte-aligned), store `ra` at `(K - 4)(sp)`, and save either incoming `a0` or callee-saved `s0` at the next word slot.
3. **Code Base Case First:** Test termination conditions before any `call`; load the base return value into `a0` and `j func_epilogue`.
4. **Recurse and Recombine:** Load child arguments into `a0`, `a1`, execute `call func`, reload live values from the stack or `s0`, and compute the return value into `a0`.
5. **Single Shared Epilogue:** Restore `s0` (if used) and `ra`, execute `addi sp, sp, K`, and `ret`.

<Callout type="warning" title="Common Mistakes">

1. **Multiplying by Clobbered `a0`:** Writing `call fact; mul a0, a0, a0` squares $f(n - 1)$ instead of multiplying by $n$ because `a0` no longer contains $n$.
2. **Skipping Epilogue Deallocation:** Executing an early `ret` from the base case after already allocating `-K` bytes misaligns `sp` and crashes the caller unwind.
3. **Missing Base-Case Branch:** Using `blt` instead of `ble` on `n <= 0` lets negative or zero inputs recurse forever until stack memory overflows.

</Callout>

Translate both single-recursion C functions below into complete RISC-V assembly (as insurance in case Question 6 includes a recursive helper):

```c
int power(int base, int exp) {
    if (exp <= 0) return 1;
    return base * power(base, exp - 1);
}

int sum_arr(int *arr, int n) {
    if (n <= 0) return 0;
    return arr[n - 1] + sum_arr(arr, n - 1);
}
```

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

```asm
# 1. power(a0 = base, a1 = exp) -> a0 = base^exp
power:
    addi sp, sp, -8
    sw   ra, 4(sp)               # Save return address
    sw   a0, 0(sp)               # Save base across recursive call

    bgt  a1, zero, pow_rec       # Base case: if (exp <= 0) return 1
    li   a0, 1
    j    pow_epilogue

pow_rec:
    addi a1, a1, -1              # exp - 1 (a0 already holds base)
    call power                   # Returns a0 = power(base, exp - 1)
    lw   t0, 0(sp)               # Reload original base
    mul  a0, t0, a0              # a0 = base * power(base, exp - 1)

pow_epilogue:
    lw   ra, 4(sp)
    addi sp, sp, 8
    ret

# 2. sum_arr(a0 = int *arr, a1 = int n) -> a0 = arr[0] + ... + arr[n - 1]
sum_arr:
    addi sp, sp, -8
    sw   ra, 4(sp)
    sw   s0, 0(sp)               # Preserve caller's s0

    bgt  a1, zero, sum_rec       # Base case: if (n <= 0) return 0
    li   a0, 0
    j    sum_epilogue

sum_rec:
    addi a1, a1, -1              # a1 = n - 1 (also prepares Arg 2!)
    slli t0, a1, 2               # Byte offset = (n - 1) * 4
    add  t0, a0, t0              # &arr[n - 1]
    lw   s0, 0(t0)               # s0 = arr[n - 1] (survives across call!)

    call sum_arr                 # Returns a0 = sum_arr(arr, n - 1)
    add  a0, s0, a0              # a0 = arr[n - 1] + sum_arr(arr, n - 1)

sum_epilogue:
    lw   s0, 0(sp)
    lw   ra, 4(sp)
    addi sp, sp, 8
    ret
```
