## Recursive Subroutines

To a RISC-V processor, recursion is not a special hardware mode—it is an ordinary `call` (`jal ra, label`) whose jump target happens to be the function's own entry label. Because every recursive invocation calls a subroutine, **every recursive function is a non-leaf function** ([Subroutine Stack Frames](/dynamic-courses/computer-architecture/04-riscv-subroutines/12-subroutine-stack-frames/)): each activation must allocate its own 16-byte-aligned stack frame to preserve **`ra`** and any live arguments or partial results needed after the recursive `jal` returns.

<Divider label="1 · Example" />

### Tracing Recursive Factorial

Let us translate and trace the recursive `fact(n)` helper from our Part IV running program for $n = 3$:

```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

When `fact(3)` runs, `a0` arrives holding `3`. Before calling `fact(2)`, `fact(3)` must overwrite `a0` with `2`, and when `fact(2)` finishes, `a0` arrives back holding the child result `2`—not the original `3`! We therefore allocate a **16-byte** stack frame in every activation, saving **`ra`** at `12(sp)` and the current parameter **`n`** (`a0`) at `8(sp)`:

```asm
# Arguments: a0 = n
# Returns:   a0 = n!
fact:
    # --- 1. PROLOGUE: 16-byte aligned activation frame ---
    addi sp, sp, -16
    sw   ra, 12(sp)          # Save caller's return address
    sw   a0, 8(sp)           # Save current n before child call overwrites a0

    # --- 2. BASE CASE: if (n <= 1) return 1 ---
    li   t0, 1
    bgt  a0, t0, fact_rec    # If n > 1, descend into recursive step
    li   a0, 1               # Base case return value = 1
    j    fact_epilogue       # Jump to shared epilogue to release our 16-byte frame

    # --- 3. RECURSIVE STEP: n * fact(n - 1) ---
fact_rec:
    addi a0, a0, -1          # Child argument: a0 = n - 1
    call fact                # Recursive jal! Returns with a0 = fact(n - 1)

    lw   t1, 8(sp)           # Reload THIS activation's saved n from 8(sp)
    mul  a0, t1, a0          # a0 = n * fact(n - 1)

    # --- 4. EPILOGUE: Restore ra, pop 16-byte frame, return ---
fact_epilogue:
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

As shown in [the figure](#fig-recursive-stack), calling `fact(3)` pushes three distinct 16-byte activation records onto the stack during **recursive descent** (`sp - 16` holding $n = 3$, `sp - 32` holding $n = 2$, and `sp - 48` holding $n = 1$). At $n = 1$, the branch `bgt a0, t0, fact_rec` is not taken: `a0` becomes `1`, frame $n = 1$ pops (`sp + 16`), and execution unwinds in strict **Last-In, First-Out (LIFO)** order—reloading $n = 2$ to compute $2 \times 1 = 2$, then reloading $n = 3$ to compute $3 \times 2 = 6$, and finally restoring `main`'s original `ra`.

<Divider label="2 · Theory" />

We generalize the factorial trace into four principles: preserving `ra` and live values across self-calls, funneling every base case through a shared epilogue, scaling the idiom to dual-branching recurrences that require two preserved values, and bounding peak stack depth $B_{\text{peak}}$.

### Recursive Frame Invariants

Every recursive C-to-RISC-V translation enforces two hardware invariants at each activation level:

1. **Unconditional `ra` Preservation:** Even though the deepest base-case activation executes no further `call`, every outer activation executes `call self` (`jal ra, self`), which overwrites `ra` with the instruction address immediately after `call self` *inside the recursive function*. If a recursive routine omits `sw ra, 12(sp)` and `lw ra, 12(sp)`, the base case returns once to `call self + 4`, and that level's `ret` jumps right back to `call self + 4` forever—trapping the CPU in an infinite loop.
2. **Shielding Live Values Across `jal`:** Register `a0` plays three conflicting roles: it brings in parameter $n$, must be overwritten with the child argument (such as $n - 1$), and returns holding $f(n - 1)$. Any value from before `call self` that appears in an expression *after* `call self` returns must be saved in the current frame using either of two equivalent ABI idioms:
   - **Caller-Slot Idiom (`sw a0, 8(sp)`):** Spill `a0` directly to a dedicated word slot in the prologue and reload it into a temporary (`lw t1, 8(sp)`) right after `call self`.
   - **Callee-Saved Idiom (`sw s0, 8(sp)`):** Save caller's `s0` in the prologue, copy `mv s0, a0`, compute child argument `addi a0, s0, -1`, and after `call self` combine `mul a0, s0, a0` before restoring `lw s0, 8(sp)` in the epilogue.

Both idioms allocate the exact same **16-byte** frame (`ra` + 1 word = 8 bytes, rounded up to 16 bytes) and earn full marks in Question 6; the `s0` idiom becomes especially convenient when $n$ is referenced multiple times after a call.

### Base Case Teardown

Always route every return path—both base case(s) and recursive step(s)—through a **single shared epilogue label** (`func_epilogue:`). Once `addi sp, sp, -16` executes at the top of the function, jumping to `ret` directly from the base case without executing `addi sp, sp, 16` leaves `sp` shifted by $-16$ bytes, corrupting the caller's stack pointer and reloading the wrong `ra`! Routing `j func_epilogue` guarantees symmetric `+16` deallocation on every exit path.

### Dual-Branching Recursion

When a recursive C function makes **two** recursive calls in the same body—such as `fib(n) = fib(n - 1) + fib(n - 2)`—two separate live values must survive across `jal`:

1. Input parameter **`n`** must survive the **first** recursive call (`call fib` for `n - 1`) so we can still compute `n - 2` for the second call.
2. Partial result **`fib(n - 1)`** (returned in `a0` by the first call) must survive the **second** recursive call (`call fib` for `n - 2`), which overwrites `a0` and may freely trash `t0`–`t6`!

Using the callee-saved idiom with **`s0`** (for `n`) and **`s1`** (for `fib(n - 1)`) keeps the code clean inside a single **16-byte** frame (`ra` + `s0` + `s1` = $12\text{ B} \implies 16\text{ B}$ aligned):

```asm
# int fib(int n) { if (n <= 0) return 0; if (n == 1) return 1; return fib(n-1) + fib(n-2); }
fib:
    addi sp, sp, -16
    sw   ra, 12(sp)          # 12(sp): return address
    sw   s0, 8(sp)           #  8(sp): caller's s0 (we store n in s0)
    sw   s1, 4(sp)           #  4(sp): caller's s1 (we store fib(n - 1) in s1)

    mv   s0, a0              # s0 = n

    # Base cases: n <= 0 -> 0, n == 1 -> 1
    ble  s0, zero, fib_ret_0
    li   t0, 1
    beq  s0, t0, fib_ret_1

    # First recursive branch: fib(n - 1)
    addi a0, s0, -1          # a0 = n - 1
    call fib
    mv   s1, a0              # Shield fib(n - 1) in callee-saved s1!

    # Second recursive branch: fib(n - 2)
    addi a0, s0, -2          # s0 still holds original n -> a0 = n - 2
    call fib                 # Returns with a0 = fib(n - 2); s1 is intact!

    add  a0, s1, a0          # a0 = fib(n - 1) + fib(n - 2)
    j    fib_epilogue

fib_ret_0:
    li   a0, 0
    j    fib_epilogue

fib_ret_1:
    li   a0, 1

fib_epilogue:
    lw   s1, 4(sp)
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

### Stack Depth Bounds

If an execution path reaches a maximum simultaneous nesting depth of $D_{\max}$ active calls and each activation allocates an aligned frame of $K$ bytes, peak stack memory consumption is:

$$B_{\text{peak}} = D_{\max} \cdot K$$

Notice that in dual-branching `fib(n)`, `fib(n - 1)` completely unwinds and pops all its frames *before* `fib(n - 2)` is called; therefore, even though dynamic instruction count grows exponentially ($\mathcal{O}(2^n)$), peak stack depth remains linear ($D_{\max} = n$, so $B_{\text{peak}} = 16n\text{ bytes}$ for $n \ge 1$). Conversely, if a recursive call is in **tail position** (the recursive call is the very last operation before `return`, with no post-call multiplication or addition), optimizing compilers (`gcc -O2`) apply **Tail-Call Optimization (TCO)**—updating `a0` in place and jumping (`j`) to the loop header with $\mathcal{O}(1)$ stack space. In hand-written Exam Q6 translations, however, always preserve the explicit recursive stack frame when the C prompt is recursive.

<Callout type="bridge" title="Embedded Firmware Bridge: Bounded Recursion in Flight Control">

Safety-critical firmware standards (**MISRA-C**, **DO-178C** avionics) ban unbounded recursion because data-dependent call depths make worst-case stack sizing undecidable. When robotics engineers implement recursive octree spatial queries or depth-first planners on embedded hardware, they either pass an explicit `depth` guard (`if (depth >= MAX_DEPTH) return ERR_BOUND;`) so $D_{\max} \cdot K$ is provably bounded, or convert the recursion into an iterative loop over a fixed-capacity static array.

</Callout>

### Recursion Pattern Reference

| Recursion Pattern | Live Values Across `call` | Saved Slots Needed | Aligned Frame $K$ | Post-Call Recombination |
| :--- | :--- | :--- | :---: | :--- |
| **Single Linear (`fact(n)`)** | Parameter `n` | `ra` + `a0` (or `s0`) = $8\text{ B}$ | $16\text{ B}$ | `lw t1, 8(sp)` $\to$ `mul a0, t1, a0` |
| **Two-Arg Linear (`power(b, e)`)** | Parameter `b` (`a0`) | `ra` + `a0` (or `s0`) = $8\text{ B}$ | $16\text{ B}$ | `lw t0, 8(sp)` $\to$ `mul a0, t0, a0` |
| **Array Linear (`sum(arr, n)`)** | Element `arr[n-1]` (or `arr`, `n`) | `ra` + `s0` = $8\text{ B}$ | $16\text{ B}$ | `add a0, s0, a0` |
| **Dual-Branching (`fib(n)`)** | Input `n` **and** 1st result | `ra` + `s0` + `s1` = $12\text{ B}$ | $16\text{ B}$ | `mv s1, a0` (1st) $\to$ `add a0, s1, a0` (2nd) |

### Recursive Translation Procedure

1. **Identify Live Post-Call Values:** Circle every variable or partial call result in the C `return` expression that is used *after* a recursive call returns.
2. **Allocate Aligned Frame & Spill:** Subtract $K = 16$ (or $32$ if $> 3$ saved words), store `ra` at `(K - 4)(sp)`, and save either incoming `a0` or callee-saved `s0`, `s1`, ... at descending word offsets.
3. **Code Base Case(s) First:** Test termination conditions before any `call`; load the base return value into `a0` and `j func_epilogue`.
4. **Code Recursive Call(s) & Recombine:** Load child arguments into `a0`, `a1`, ..., execute `call func`, reload/shield live values from stack slots or `s0`–`s1`, and compute the return value into `a0`.
5. **Single Shared Epilogue:** Restore `s` registers and `ra`, execute `addi sp, sp, K`, and `ret`.

<Callout type="warning" title="Common Mistakes">

1. **Multiplying by `a0` Instead of Reloaded `n`:** Writing `call fact; mul a0, a0, a0` squares $f(n - 1)$ instead of multiplying by $n$ because `a0` no longer contains $n$.
2. **Early `ret` Skipping `addi sp, sp, 16`:** Returning directly from the base case after already allocating `-16` bytes misaligns `sp` and crashes the first caller unwind.
3. **Storing First Branch Result in `t0`:** In `F(n - 1) + F(n - 2)`, keeping `F(n - 1)` in `t0` across the second recursive call overwrites ancestor results at deeper levels.
4. **Missing Base-Case Branch:** Using `blt` instead of `ble` on `n <= 0` lets negative or zero inputs recurse forever until stack memory overflows.

</Callout>

```asm
# Arguments: a0 = int *arr, a1 = int n
# Returns:   a0 = arr[0] + ... + arr[n - 1]
sum_arr:
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)               # Preserve caller's s0

    # Base case: if (n <= 0) return 0
    bgt  a1, zero, sum_rec
    li   a0, 0
    j    sum_epilogue

sum_rec:
    # Fetch arr[n - 1] into callee-saved s0 BEFORE calling sum_arr(arr, n - 1)
    addi a1, a1, -1              # a1 = n - 1 (also prepares Arg 2 for child call!)
    slli t0, a1, 2               # Byte offset = (n - 1) * 4
    add  t0, a0, t0              # Address &arr[n - 1]
    lw   s0, 0(t0)               # s0 = arr[n - 1] (survives across call!)

    # Arg 1 (a0 = arr) and Arg 2 (a1 = n - 1) are both ready
    call sum_arr                 # Returns with a0 = sum_arr(arr, n - 1)

    add  a0, s0, a0              # a0 = arr[n - 1] + sum_arr(arr, n - 1)

sum_epilogue:
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

```c
int pell(int n) {
    if (n <= 0) return 0;
    if (n == 1) return 1;

}

int main(void) {
    char tag[16];
    int len, n, ans;

    printf("Sensor tag: ");
    scanf("%s", tag);
    len = strlen(tag);

    do {
        printf("Order n (0..10): ");
        scanf("%d", &n);

    printf("[%d] Pell = %d\n", len, ans);
    return 0;
}
```

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

```asm
.data
str_tag:  .asciz "Sensor tag: "
str_ord:  .asciz "Order n (0..10): "
str_lbr:  .asciz "["
str_mid:  .asciz "] Pell = "

.text
.globl main

# ==============================================================================
# MAIN: tag[16] (0..15) + pad (16..19) + s1 (20) + s0 (24) + ra (28) = 32 B
# ==============================================================================
main:
    addi sp, sp, -32
    sw   ra, 28(sp)
    sw   s0, 24(sp)              # s0 = len
    sw   s1, 20(sp)              # s1 = validated n, then ans

    # 1. Read tag into stack buffer [sp + 0 .. sp + 15] and compute len
    la   a0, str_tag
    li   a7, 4
    ecall

    addi a0, sp, 0
    li   a1, 16
    li   a7, 8
    ecall

    addi a0, sp, 0
    call strlen
    mv   s0, a0                  # s0 = len

    # 2. Validate 0 <= n <= 10
ask_order:
    la   a0, str_ord
    li   a7, 4
    ecall

    li   a7, 5                   # ReadInt
    ecall
    mv   s1, a0                  # s1 = n

    blt  s1, zero, ask_order     # Retry if n < 0
    li   t0, 10
    blt  t0, s1, ask_order       # Retry if n > 10

    # 3. ans = pell(n)
    mv   a0, s1
    call pell
    mv   s1, a0                  # s1 = ans

    # 4. printf("[%d] Pell = %d\n", len, ans)
    la   a0, str_lbr
    li   a7, 4
    ecall

    mv   a0, s0                  # len
    li   a7, 1
    ecall

    la   a0, str_mid
    li   a7, 4
    ecall

    mv   a0, s1                  # ans
    li   a7, 1
    ecall

    li   a0, 10                  # '\n'
    li   a7, 11
    ecall

    # 5. Epilogue & Clean Exit
    lw   s1, 20(sp)
    lw   s0, 24(sp)
    lw   ra, 28(sp)
    addi sp, sp, 32

    li   a7, 10
    ecall

# ==============================================================================
# RECURSIVE HELPER: pell(a0 = n) -> a0 = 2 * pell(n - 1) + pell(n - 2)
# Frame: 16 B (ra at 12(sp), s0 = n at 8(sp), s1 = 2*pell(n-1) at 4(sp))
# ==============================================================================
pell:
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    sw   s1, 4(sp)

    mv   s0, a0                  # s0 = n
    ble  s0, zero, pell_zero
    li   t0, 1
    beq  s0, t0, pell_one

    # First recursive call: 2 * pell(n - 1)
    addi a0, s0, -1
    call pell
    slli s1, a0, 1               # s1 = 2 * pell(n - 1) (shielded in s1!)

    # Second recursive call: pell(n - 2)
    addi a0, s0, -2
    call pell                    # a0 = pell(n - 2)

    add  a0, s1, a0              # a0 = 2 * pell(n - 1) + pell(n - 2)
    j    pell_epilogue

pell_zero:
    li   a0, 0
    j    pell_epilogue

pell_one:
    li   a0, 1

pell_epilogue:
    lw   s1, 4(sp)
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```
