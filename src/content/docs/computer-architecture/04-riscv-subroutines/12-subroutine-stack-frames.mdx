## Subroutine Stack Frames

As soon as `main` invokes a helper subroutine such as `call strlen`, the processor executes `jal ra, strlen` and overwrites register **`ra`** with the return address inside `main`, while the helper itself needs working registers and local storage without corrupting `main`'s variables. The RISC-V **Application Binary Interface (ABI)** solves both hazards with a strict division between volatile caller-saved registers and preserved callee-saved registers, backed by word-aligned **stack frames** allocated downward from the stack pointer **`sp`**.

<Divider label="1 · Example" />

### Dual-Buffer Main Frame

Before stating general ABI rules, let us budget and trace a concrete non-leaf `main` function that allocates two local 16-byte C arrays on the stack, calls `strlen` ([Arrays and Strings](/dynamic-courses/computer-architecture/03-riscv-instructions/10-arrays-and-strings/)) on each buffer, and prints the sum of their lengths:

```c
int main(void) {
    char prima[16];
    char seconda[16];
    int len1, len2;

    scanf("%s", prima);
    len1 = strlen(prima);
    scanf("%s", seconda);
    len2 = strlen(seconda);

    printf("%d\n", len1 + len2);
    return 0;
}
```

Because `prima` and `seconda` are declared locally inside `main`, they belong on the **runtime stack**, not in `.data`. In addition, `main` calls `strlen` twice: it must save **`ra`** (because `main` is a non-leaf function) and keep `len1` in callee-saved register **`s0`** (and `len2` in **`s1`**) so the second `call strlen` cannot clobber `len1`. Summing the raw storage requirements gives:

$$\underbrace{16\text{ B}}_{\texttt{prima[16]}} + \underbrace{16\text{ B}}_{\texttt{seconda[16]}} + \underbrace{4\text{ B}}_{\texttt{s1}} + \underbrace{4\text{ B}}_{\texttt{s0}} + \underbrace{4\text{ B}}_{\texttt{ra}} = 44\text{ B}$$

Because `44 B` is already a multiple of 4 bytes, a RARS exam solution can allocate `addi sp, sp, -44` directly; under the strict 16-byte compiler ABI convention, rounding $44\text{ B}$ up to the nearest multiple of $16\text{ B}$ yields **$K = 48\text{ bytes}$** (`32(sp)`–`35(sp)` remains 4-byte alignment padding, as shown below):

Matching the layout in [the figure](#fig-stack-frame), `prima` starts at `sp + 0`, `seconda` starts at `sp + 16`, and `strlen` executes at the bottom as a **leaf function** using only `t0`–`t1` with zero stack overhead:

```asm
.text
.globl main

main:
    # --- PROLOGUE: Allocate 48-byte frame (48 mod 16 == 0) ---
    addi sp, sp, -48
    sw   ra, 44(sp)          # Save return address
    sw   s0, 40(sp)          # Save s0 (will hold len1)
    sw   s1, 36(sp)          # Save s1 (will hold len2)

    # 1. Read prima into stack slot [sp + 0 .. sp + 15]
    addi a0, sp, 0           # a0 = &prima[0]
    li   a1, 16
    li   a7, 8               # ReadString
    ecall

    addi a0, sp, 0           # Pass &prima[0] to strlen
    call strlen              # jal ra, strlen -> returns length in a0
    mv   s0, a0              # s0 = len1 (survives across the next call!)

    # 2. Read seconda into stack slot [sp + 16 .. sp + 31]
    addi a0, sp, 16          # a0 = &seconda[0]
    li   a1, 16
    li   a7, 8               # ReadString
    ecall

    addi a0, sp, 16          # Pass &seconda[0] to strlen
    call strlen
    mv   s1, a0              # s1 = len2

    # 3. Print len1 + len2 followed by '\n'
    add  a0, s0, s1
    li   a7, 1               # PrintInt
    ecall

    li   a0, 10
    li   a7, 11              # PrintChar ('\n')
    ecall

    # --- EPILOGUE: Restore saved registers & release 48-byte frame ---
    lw   s1, 36(sp)
    lw   s0, 40(sp)
    lw   ra, 44(sp)
    addi sp, sp, 48

    li   a7, 10              # Clean Exit
    ecall

# Leaf helper: uses only caller-saved t0, t1 -> 0 stack bytes needed
strlen:
    mv   t0, a0
strlen_loop:
    lbu  t1, 0(t0)
    beqz t1, strlen_done
    addi t0, t0, 1
    j    strlen_loop
strlen_done:
    sub  a0, t0, a0
    ret                      # Expands to: jalr zero, 0(ra)
```

<Divider label="2 · Theory" />

Safe multi-function execution rests on four rules: dividing registers into caller-saved and callee-saved sets, distinguishing leaf from non-leaf procedures, sizing 16-byte-aligned prologue/epilogue frames, and addressing local C arrays inside the stack frame.

### Caller and Callee Registers

Without a shared register convention, every function call would have to spill all 31 general-purpose registers to memory just in case the callee modified them. Instead, the RISC-V RV32 ABI splits registers into two preservation contracts:

1. **Caller-Saved Registers** (`t0`–`t6`, `a0`–`a7`, `ra`):
   - **`t0`–`t6`** (`x5`–`x7`, `x28`–`x31`) are scratch temporaries, **`a0`–`a7`** (`x10`–`x17`) carry up to 8 incoming arguments (with return values placed in **`a0`**–**`a1`**), and **`ra`** (`x1`) holds the return address written by `jal`.
   - A callee may overwrite `t0`–`t6` and `a0`–`a7` freely without saving or restoring them. Never assume a value left in `t0` or `a0` before `call helper` still exists after `call helper` returns.
2. **Callee-Saved Registers** (`s0`–`s11`, `sp`):
   - **`s0`–`s11`** (`x8`–`x9`, `x18`–`x27`) and the stack pointer **`sp`** (`x2`) are guaranteed unchanged across any `call`.
   - If a callee chooses to modify `s0`, the callee **must** save the caller's old `s0` onto its stack frame in its prologue and restore `s0` in its epilogue before `ret`. Because every compliant callee honors this contract, a caller can keep loop indices (`i`) and intermediate results (`len1`) safely inside `s0`–`s11` across any number of subroutine and `ecall` invocations.

### Leaf and Non-Leaf Functions

Every procedure in a call graph belongs to one of two structural classes that determine whether `ra` must be spilled to memory:

- **Leaf Function:** Invokes **no** other subroutines inside its body (neither `call` nor `jal`). Because `ra` still holds the return address placed there by the caller, and because all temporary arithmetic can live inside volatile `t0`–`t6` and `a0`–`a7`, a leaf helper without large local arrays executes with **zero stack frame allocation** and returns in one instruction via `ret` (`jalr zero, 0(ra)`).
- **Non-Leaf Function:** Invokes at least one subroutine via `call target` (which expands to `auipc` + `jalr` or `jal ra, target`). Hardware execution of `jal` overwrites `ra` with `PC + 4` inside the non-leaf function, permanently destroying the non-leaf function's own return address unless **`ra` was saved** onto the stack in the prologue.

### Prologue and Epilogue Template

The RISC-V runtime stack grows **downward** toward lower byte addresses: subtracting from `sp` allocates space, and adding the exact same constant back to `sp` deallocates it. In RARS RV32 assembly, allocate the exact **4-byte word multiple** needed for your buffers and saved registers (standard Linux/GCC compilers round frames up to 16-byte multiples, which is optional in RARS as long as every `sw`/`lw` slot is 4-byte aligned):

$$K = 4 \cdot \left\lceil \frac{B_{\text{buffers}}}{4} \right\rceil + 4 \cdot N_{\text{regs}}$$

Inside the allocated $K$-byte frame, place local arrays starting at `0(sp)` upward and store saved registers in descending 4-byte word slots from the top of the frame: `ra` at `(K - 4)(sp)`, `s0` at `(K - 8)(sp)`, `s1` at `(K - 12)(sp)`, and so on. Every non-leaf procedure follows one mechanical **prologue–body–epilogue** skeleton:

```asm
non_leaf_fn:
    # --- PROLOGUE ---
    addi sp, sp, -12         # 1. Allocate 4-byte word-aligned frame (ra + s0 + s1 = 12 B)
    sw   ra, 8(sp)           # 2. Save ra at top word slot (K - 4)
    sw   s0, 4(sp)           # 3. Save every s-register modified in this function
    sw   s1, 0(sp)

    # --- BODY ---
    mv   s0, a0              # Keep live parameter across nested calls
    call helper_fn           # Safe: ra, s0, s1 are backed up in our frame
    add  a0, a0, s0          # Place final return value in a0

    # --- EPILOGUE (exact mirror of prologue) ---
    lw   s1, 0(sp)           # 1. Restore saved s-registers
    lw   s0, 4(sp)
    lw   ra, 8(sp)           # 2. Restore original return address
    addi sp, sp, 12          # 3. Deallocate frame (+K matches -K)
    ret                      # 4. Return to caller: jalr zero, 0(ra)
```

### Stack Buffers and Exam Rules

When a C function declares a local array such as `char buf[16];` or `int vec[4];`, allocate those bytes at low offsets (`0(sp)`, `16(sp)`, ...) inside the function's stack frame and compute the base pointer using **`addi`**:

```asm
addi a0, sp, 0               # a0 = &buf[0] (pointer to stack slot sp + 0)
addi a1, sp, 16              # a1 = &second_buf[0] (pointer to stack slot sp + 16)
```

Never return the address of a local stack array (`addi a0, sp, 0` followed by `addi sp, sp, K; ret`) to a caller: once `sp` moves back up, that memory lies below `sp` and will be overwritten by the very next function call or interrupt.

Two practical conventions govern Question 6 grading in RARS:

1. **Register-Named C Variables:** Exam prompts frequently write leaf C helpers with local integers deliberately named `int s0, s1, s2;`. In C, `s0` is an ordinary variable identifier, **not** an instruction to touch hardware register `x8`! Inside a leaf helper, map all local C variables to caller-saved temporaries (`t0`–`t6`). Writing to hardware `s0` inside a zero-stack leaf helper silently clobbers `main`'s loop counter `s0`!
2. **Self-Contained RARS File:** RARS does not link `libc`. Whenever C code calls `strlen`, append the leaf `strlen` subroutine directly at the bottom of `.text` so all labels assemble without unresolved symbol errors.

<Callout type="bridge" title="RTOS Stack Guard Pages">

On desktop Linux, overflowing the stack crosses an unmapped virtual **guard page** and triggers a clean `SIGSEGV` fault. On bare-metal Cortex-M and RISC-V flight controllers running FreeRTOS without full virtual memory, every task's stack sits right next to another task's TCB or global RAM: allocating `char frame_buf[4096]` on a $2\text{ KiB}$ thread stack silently corrupts neighboring tasks mid-flight. Embedded engineers place large buffers in static SRAM or DMA pools and audit worst-case frame sums at compile time (`-fstack-usage`).

</Callout>

### ABI Preservation Reference

| Register(s) | Hardware Names | ABI Role | Preserved Across `call`? | Mechanical Rule |
| :--- | :---: | :--- | :---: | :--- |
| **`zero`** | `x0` | Hardwired constant `0` | Immutable | Reads `0`; writes discarded |
| **`ra`** | `x1` | Return address | **No** (clobbered by `jal`) | Non-leaf functions **must** `sw ra, (K-4)(sp)` |
| **`sp`** | `x2` | Stack pointer | **Yes** (Callee-saved) | Word-align ($K \bmod 4 = 0$); match `-K` and `+K` |
| **`a0`–`a1`** | `x10`–`x11` | Args 1–2 & return values | **No** (Caller-saved) | Move needed inputs to `s0`–`s11` before `call` |
| **`a2`–`a7`** | `x12`–`x17` | Args 3–8 (`a7` = syscall ID) | **No** (Caller-saved) | Freely overwritten by callees and `ecall` |
| **`t0`–`t6`** | `x5`–`x7`, `x28`–`x31` | Scratch temporaries | **No** (Caller-saved) | Default registers for leaf helper variables |
| **`s0`–`s11`** | `x8`–`x9`, `x18`–`x27` | Saved local variables | **Yes** (Callee-saved) | Save in prologue & restore in epilogue if used |

### Stack Frame Budgeting Procedure

1. **Classify the Function:** If it makes zero `call`/`jal` instructions and has no local arrays, write a **zero-stack leaf** using only `t0`–`t6` and `a0`–`a7`, ending with `ret`.
2. **Sum Raw Frame Bytes:** For a non-leaf function (or one with local arrays), sum all local buffer capacities (padded to 4-byte multiples if needed) plus $4\text{ bytes}$ for `ra` and $4\text{ bytes}$ for each `s` register modified by the function (rounding up to a 16-byte multiple is optional under RARS).
3. **Assign Non-Overlapping Offsets:** Place local arrays starting at `0(sp)` upward, and place saved registers at consecutive 4-byte offsets above the arrays (`s0`, `s1`, ..., `ra`).
4. **Mirrored Prologue & Epilogue:** Emit `addi sp, sp, -K` + `sw` stores at entry, pass stack buffer pointers via `addi aX, sp, offset`, and emit matching `lw` loads + `addi sp, sp, K` + `ret` (or `ecall 10` in `main`) at exit.

<Callout type="warning" title="Common Mistakes">

1. **Stack Arrays in `.data`:** Declaring `prima: .space 16` in `.data` when C declares `char prima[16];` inside `main()` violates stack allocation rules (and breaks re-entrancy).
2. **Forgetting `sw ra`:** Without `sw ra, (K-4)(sp)` in non-leaf routines or `main`, the first `call` overwrites `ra`.
3. **Loading Instead of Addressing:** Writing `lw a0, 0(sp)` instead of `addi a0, sp, 0` loads the first 4 characters inside the buffer rather than computing `&buf[0]`.
4. **Mismatched Frame Sizes:** Subtracting `-24` in the prologue and adding `+28` in the epilogue (or failing to round `char` buffer sizes to 4-byte word boundaries before storing `sw` words above them) causes unaligned memory traps.

</Callout>

```c
int elabora(char *p, char *s, int n) {
    int i, v, ris = 0, t = 1;
    for (i = n - 1; i >= 0; i--) {
        v = p[i] - s[i];
        if (v >= 1) ris = ris + v * t;
        t = t * 10;
    }
    return ris;
}

int main(void) {
    char prima[16], seconda[16];
    int i, pa2, res;
    for (i = 0; i < 3; i++) {
        printf("Inserisci una prima stringa di numeri\n");
        scanf("%s", prima);
        pa2 = strlen(prima);
        do {
            printf("Inserisci una seconda stringa di numeri della stessa dimensione\n");
            scanf("%s", seconda);
        } while (strlen(seconda) != pa2);

        res = elabora(prima, seconda, pa2);
        printf("%d ) Risultato = %d\n", i, res);
    }
    return 0;
}
```

main:
    addi sp, sp, -48
    sw   ra, 44(sp)
    sw   s0, 40(sp)              # s0 = loop index i
    sw   s1, 36(sp)              # s1 = pa2 = strlen(prima)
    sw   s2, 32(sp)              # s2 = res = elabora(...)

    li   s0, 0                   # i = 0

for_main:
    li   t0, 3
    bge  s0, t0, exit_main       # Exit loop when i >= 3

    # 1. Read prima and measure pa2 = strlen(prima)
    la   a0, str_prompt1
    li   a7, 4

    addi a0, sp, 0               # &prima[0]
    li   a1, 16
    li   a7, 8
    ecall

    addi a0, sp, 0
    call strlen
    mv   s1, a0                  # s1 = pa2

    # 2. do-while: read seconda until strlen(seconda) == pa2
do_seconda:
    la   a0, str_prompt2
    li   a7, 4
    ecall

    addi a0, sp, 16              # &seconda[0]
    li   a1, 16
    li   a7, 8
    ecall

    addi a0, sp, 16
    call strlen
    bne  a0, s1, do_seconda      # Repeat if strlen(seconda) != pa2

    # 3. res = elabora(prima, seconda, pa2)
    addi a0, sp, 0               # Arg 1: prima
    addi a1, sp, 16              # Arg 2: seconda
    mv   a2, s1                  # Arg 3: pa2
    call elabora
    mv   s2, a0                  # s2 = res

    # 4. printf("%d ) Risultato = %d\n", i, res)
    mv   a0, s0
    li   a7, 1
    ecall

    la   a0, str_fmt_idx
    li   a7, 4
    ecall

    mv   a0, s2
    li   a7, 1
    ecall

    li   a0, 10
    li   a7, 11                  # '\n'
    ecall

    addi s0, s0, 1               # i++
    j    for_main

exit_main:
    lw   s2, 32(sp)
    lw   s1, 36(sp)
    lw   s0, 40(sp)
    lw   ra, 44(sp)
    addi sp, sp, 48

    li   a7, 10
    ecall

# Leaf helper: elabora(a0 = char *p, a1 = char *s, a2 = int n) -> a0 = ris
elabora:
    li   t1, 0                   # ris = 0
    li   t2, 1                   # t = 1
    addi t0, a2, -1              # i = n - 1

elabora_loop:
    blt  t0, zero, elabora_done

    add  t4, a0, t0
    lbu  t5, 0(t4)               # p[i]
    add  t4, a1, t0
    lbu  t6, 0(t4)               # s[i]
    sub  t3, t5, t6              # v = p[i] - s[i]

    li   t4, 1
    blt  t3, t4, skip_accum
    mul  t5, t3, t2
    add  t1, t1, t5              # ris += v * t

skip_accum:
    li   t4, 10
    mul  t2, t2, t4              # t *= 10

elabora_done:

    ret

# Leaf helper: strlen(a0 = char *str) -> a0 = length (strips '\n' to '\0')

    mv   t0, a0

strlen_loop:

    j    strlen_loop

    mv   a1, s1                  # Arg 2: pa1
    mv   a2, s2                  # Arg 3: pa2
    call processa
    mv   s3, a0                  # s3 = ris

    blt  s3, zero, main_do       # while (ris < 0)

    la   a0, str_res
    li   a7, 4
    ecall

    mv   a0, s3
    li   a7, 1
    ecall

    li   a0, 10
    li   a7, 11
    ecall

    addi s0, s0, 1
    j    main_for

main_exit:
    lw   s3, 8(sp)
    lw   s2, 12(sp)
    lw   s1, 16(sp)
    lw   s0, 20(sp)
    lw   ra, 24(sp)
    addi sp, sp, 28

    li   a7, 10
    ecall

# Leaf helper: processa(a0 = char *p0, a1 = int n, a2 = int a2) -> a0 = ris
processa:
    mv   t0, a2                  # p = a2
    li   t1, 0                   # ris = 0
    addi t2, a1, -1              # k = n - 1
    li   t3, 10

proc_while:
    blt  t2, zero, proc_done

    rem  t4, t0, t3              # t = p % 10
    add  t5, a0, t2              # &p0[k]
    lbu  t5, 0(t5)               # p0[k]
    addi t5, t5, -48             # p0[k] - 48
    sub  t5, t5, t4              # v = p0[k] - 48 - t
    add  t1, t1, t5              # ris += v

    div  t0, t0, t3              # p = p / 10
    bnez t0, proc_next           # Inverted (p == 0 && k > 0)
    ble  t2, zero, proc_next
    li   a0, -1                  # return -1
    ret

proc_next:
    addi t2, t2, -1              # k--
    j    proc_while

proc_done:
    mv   a0, t1
    ret

strlen:
    mv   t0, a0
    li   t2, 10
sl_loop2:
    lbu  t1, 0(t0)
    beqz t1, sl_done2
    beq  t1, t2, sl_strip2
    addi t0, t0, 1
    j    sl_loop2
sl_strip2:
    sb   zero, 0(t0)
sl_done2:
    sub  a0, t0, a0
    ret
