## Sequential Fall-Through

Unless a branch or jump alters the Program Counter, a RISC-V processor advances sequentially from one 32-bit instruction to the next ($\text{PC} \leftarrow \text{PC} + 4$) as established in [RISC-V Instructions](/dynamic-courses/computer-architecture/03-riscv-instructions/08-riscv-instructions/). Structured C statements (`if`, `for`, `while`) enter a guarded block when a condition is **true**, whereas assembly keeps the guarded body inline and branches **around** it whenever the **inverted** condition holds.

<Divider label="1 · Example" />

### Guarded Digit Accumulation

Consider a 4-character prefix loop adapted from our shared telemetry routine in [Part III Introduction](/dynamic-courses/computer-architecture/03-riscv-instructions/00-introduction/). Given `char *pkt` in `a0`, the loop accumulates leading ASCII digits (`'0'` $= 48$ through `'9'` $= 57$) into `sum` and stops immediately via `break` on the first non-digit character:

```c
int sum = 0;
for (int i = 0; i < 4; i++) {
    if (pkt[i] >= 48 && pkt[i] <= 57) {
        sum = sum * 10 + (pkt[i] - 48);
    } else {
        break;
    }
}
```

Translating this snippet into RV32IM (`t0 = sum`, `t1 = i`) flips every entry test into a forward branch toward the next execution target, matching the control topology in [the figure](#fig-branch-inversion):

```asm
    li   t0, 0                # sum = 0
    li   t1, 0                # i = 0
    li   t2, 4                # Loop bound 4
    li   t5, 48               # ASCII '0'
    li   t6, 57               # ASCII '9'

parse_loop:
    bge  t1, t2, parse_done   # Inverted i < 4: if i >= 4, exit loop
    add  t3, a0, t1           # t3 = &pkt[i]
    lbu  t4, 0(t3)            # t4 = pkt[i]

    blt  t4, t5, non_digit    # Inverted pkt[i] >= 48: if < 48, go to else
    bgt  t4, t6, non_digit    # Inverted pkt[i] <= 57: if > 57, go to else

    li   t3, 10
    mul  t0, t0, t3           # sum = sum * 10
    addi t4, t4, -48          # pkt[i] - 48
    add  t0, t0, t4           # sum += (pkt[i] - 48)
    j    parse_step           # Jump over else block

non_digit:
    j    parse_done           # break -> jump directly to loop exit

parse_step:
    addi t1, t1, 1            # i++
    j    parse_loop           # Repeat loop

parse_done:
```

Tracing `pkt = "47X9"` (`52, 55, 88, 57`) confirms how the four branch instructions steer execution:
- **`i = 0, 1`** (`'4'`, `'7'`): `bge`, `blt`, and `bgt` all fall through, updating `sum` to $4$ and then $47$ before `j parse_step` skips `non_digit`.
- **`i = 2`** (`'X' = 88`): `blt` ($88 < 48$) falls through, `bgt` ($88 > 57$) **takes** the jump to `non_digit`, and `j parse_done` exits the loop immediately with `sum = 47` (`'9'` at `i = 3` is never inspected).

<Divider label="2 · Theory" />

Translating structured C control flow into flat assembly proceeds in four steps: first establishing how B-type branches negate signed and unsigned relations, then applying that inversion rule to `if`/`else` selection blocks and short-circuit `&&`/`||` guards, and finally assembling top-tested and bottom-tested loop templates with `break` and `continue`.

### Condition Inversion and Signedness

RV32I provides six hardware **B-type** conditional branch instructions (`beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu`), each encoding a 12-bit signed halfword offset shifted left by $1$ bit ($\pm 4\text{ KiB}$ PC-relative range). Standard relational pseudoinstructions (`bgt`, `ble`, `bgtu`, `bleu`, `beqz`, `bnez`) assemble into single hardware instructions by swapping `rs1` and `rs2` or substituting `zero`:

$$\texttt{bgt rs1, rs2, L} \;\equiv\; \texttt{blt rs2, rs1, L}, \qquad \texttt{ble rs1, rs2, L} \;\equiv\; \texttt{bge rs2, rs1, L}$$

$$\texttt{beqz rs1, L} \;\equiv\; \texttt{beq rs1, zero, L}, \qquad \texttt{bnez rs1, L} \;\equiv\; \texttt{bne rs1, zero, L}$$

When negating a C condition to skip a guarded block, strict inequalities (`<`, `>`) flip into inclusive inequalities (`>=`, `<=`), and vice versa:

$$\neg(a < b) \iff a \ge b, \qquad \neg(a \le b) \iff a > b$$

Choosing between **signed** (`blt`, `bge`, `bgt`, `ble`) and **unsigned** (`bltu`, `bgeu`, `bgtu`, `bleu`) branches depends on the C operand type:
- **Signed** (`int`, `signed char`): Interprets bit $31$ as a two's complement sign bit, so `0xFFFFFFFF` ($-1$) satisfies `-1 < 0` (`blt` taken).
- **Unsigned** (`unsigned int`, pointers, `lbu`): Treats all $32$ bits as magnitude, so `0xFFFFFFFF` ($4{,}294{,}967{,}295$) is strictly greater than `0` (`bltu` not taken).

### Selection Templates

1. **Simple `if`:** Emit one inverted branch jumping to `skip_if`:

```asm
    # C: if (v >= 1) { ris = ris + v * t; }
    li   t3, 1
    blt  t0, t3, skip_if      # Inverted v >= 1: skip when v < 1
    mul  t4, t0, t2
    add  t1, t1, t4
skip_if:
```

**2. Complete `if-else`:** Jump to `else_blk` on the inverted condition, and place an **unconditional `j end_if`** at the bottom of the `then` block so execution never falls into `else_blk`:

```asm
    # C: if (num < 26) { val += num; } else { err = 1; }
    li   t3, 26
    bge  t0, t3, else_blk     # Inverted num < 26: jump to else when num >= 26
    add  t1, t1, t0           # then body: val += num
    j    end_if               # Mandatory jump over else_blk!
else_blk:
    li   t2, 1                # else body: err = 1
end_if:
```

3. **Multi-Way `else if`:** Chain each negated test to the label of the next `else if` clause, ending every taken branch (except the last) with `j end_cond`:

```asm
    # C: if (c > ref) { hi++; } else if (c < ref) { lo++; }
    ble  t0, a1, check_less   # If c <= ref, test next clause
    addi t2, t2, 1            # hi++
    j    end_cond
check_less:
    bge  t0, a1, end_cond     # If c >= ref, neither clause holds
    addi t3, t3, 1            # lo++
end_cond:
```

### Short-Circuit Compound Guards

C evaluates logical **AND (`&&`)** and **OR (`||`)** from left to right, stopping as soon as the outcome is decided:

- **Logical AND** (`if (A && B)`): Both clauses must hold. Test `!A` first and jump to `skip_body`; if $A$ succeeded, test `!B` and jump to the **same** `skip_body` label:
  ```asm
      # C: if (x >= lo && x < hi) { count++; }
      blt  t0, t1, skip_body  # Clause 1 false (x < lo) -> short-circuit out
      bge  t0, t2, skip_body  # Clause 2 false (x >= hi) -> exit
      addi t3, t3, 1          # Executes only when both clauses hold
  skip_body:
  ```
  Preserving left-to-right order is essential when clause $A$ guards a pointer dereference or division in clause $B$ (such as `if (a != 0 && b / a > 2)`).

- **Logical OR** (`if (A || B)`): Either clause suffices to enter the body. Test $A$ **positively** to jump straight into `exec_body`, then test `!B` **inverted** to jump past `exec_body`:
  ```asm
      # C: if (c == 32 || c == 9) { spaces++; }
      li   t1, 32
      beq  t0, t1, exec_body  # Clause 1 true -> enter body immediately!
      li   t1, 9
      bne  t0, t1, skip_body  # Clause 2 also false -> skip body
  exec_body:
      addi t2, t2, 1          # spaces++
  skip_body:
  ```

### Loop Translation Templates

1. **Top-Tested Loops** (`for` / `while`): Both `while (cond)` and `for (init; cond; step)` place `init` once before the loop label, test `!cond` at the top to jump to `loop_exit`, execute the body and `step`, and jump back to `loop_top` with `j`:

```asm
    # Descending C loop: for (i = n - 1; i >= 0; i--) { ... }
    addi t0, a2, -1           # init: i = n - 1
for_top:
    blt  t0, zero, for_exit   # Inverted i >= 0: exit when i < 0
    # ... loop body ...
for_step:
    addi t0, t0, -1           # step: i--
    j    for_top
for_exit:
```

2. **Bottom-Tested `do-while` Loop:** Unlike `while` and `for`, a `do { ... } while (cond);` loop executes its body **at least once** and tests `cond` at the bottom to decide whether to repeat. Because jumping back repeats the loop, leave the `do-while` condition **un-inverted**:

```asm
    # C input validation: do { ... } while (len != target);
do_top:
    # ... loop body updates len in t0 ...
    bne  t0, s1, do_top       # Non-inverted: if len != target, repeat!
```

3. **`break` and `continue`:**
- **`break`:** Compiles to `j for_exit` (or a direct conditional branch `beq t1, t2, for_exit`), exiting the innermost enclosing loop immediately.
- **`continue`:** Skips the rest of the current iteration—jumping to `for_step` in a `for` loop (so `i++` still runs!) or to `while_top` in a `while` loop.

<Callout type="bridge" title="Predictable Control Timing in Robotics Firmware">

In $1\text{ kHz}$ quadrotor attitude controllers, taken versus untaken branches alter instruction fetch flow and can introduce small cycle-count variations. For tight saturation checks (`clamping` an actuator command to $[-u_{\max}, +u_{\max}]$), embedded compilers weigh short forward branches against branch-free `slt`/mask sequences depending on pipeline branch penalties.

</Callout>

### Condition Inversion and Control Lookup

| High-Level C Test | Inverted Skip Condition | Signed RV32I Skip Branch | Unsigned RV32I Skip Branch |
| :---: | :---: | :---: | :---: |
| `a == b` | `a != b` | `bne rs1, rs2, skip` | `bne rs1, rs2, skip` |
| `a != b` | `a == b` | `beq rs1, rs2, skip` | `beq rs1, rs2, skip` |
| `a < b` | `a >= b` | `bge rs1, rs2, skip` | `bgeu rs1, rs2, skip` |
| `a <= b` | `a > b` | `bgt rs1, rs2, skip` | `bgtu rs1, rs2, skip` |
| `a > b` | `a <= b` | `ble rs1, rs2, skip` | `bleu rs1, rs2, skip` |
| `a >= b` | `a < b` | `blt rs1, rs2, skip` | `bltu rs1, rs2, skip` |

| C Construct | Assembly Skeleton | Critical Rule |
| :--- | :--- | :--- |
| **`if-else`** | `b_inv else` $\to$ `then` $\to$ `j end` $\to$ `else:` | Never omit `j end` before `else:` |
| **Logical AND** (`A && B`) | `b_inv_A skip` $\to$ `b_inv_B skip` $\to$ `body` | First failure jumps straight to `skip:` |
| **Logical OR** (`A \|\| B`) | `b_pos_A body` $\to$ `b_inv_B skip` $\to$ `body:` | First success jumps straight to `body:` |
| **`for` / `while`** | `init` $\to$ `top: b_inv exit` $\to$ `body` $\to$ `step` $\to$ `j top` | Invert top test; place `step` before `j top` |
| **`do-while`** | `top:` $\to$ `body` $\to$ `b_pos top` | Do **not** invert bottom repeat test |

### Control Translation Procedure

1. **Prefix All Labels:** Give every `if` and loop function-scoped labels (`count_loop`, `count_skip`, `count_done`) so labels never collide across `main` and helper routines.
2. **Invert Header Guards:** For `if`, `else if`, `while`, and `for`, replace the C condition with its exact logical negation from the table above (checking signed vs. unsigned types).
3. **Wire Multi-Arm Merges:** Place `j end_if` at the end of every `then` and `else if` block, and `j loop_top` after the loop `step`.
4. **Check Bottom-Tested Loops:** For `do-while`, keep the C condition un-inverted on the backward branch to `do_top`.

<Callout type="warning" title="Common Mistakes">

1. **Fall-Through into `else`:** Forgetting `j end_if` at the end of `then` executes **both** the `then` body and the `else` body whenever the `if` condition is true.
2. **Inverting `do-while`:** Writing `beq t0, s1, do_top` for `while (len != target)` exits on invalid input and loops infinitely on valid input.
3. **Boundary Off-by-One** (`ble` vs `bge`): Translating `for (i = 0; i < n; i++)` with `bgt t0, a1, exit` instead of `bge t0, a1, exit` runs one extra out-of-bounds iteration at `i = n`.
4. **Duplicate Label Names:** Defining `loop:` in both `main` and a helper subroutine triggers an assembler duplicate-symbol error.

</Callout>

```asm
    bge  a0, zero, set_zero   # Inverted x < 0: if x >= 0, jump to else

set_zero:
    li   t0, 0                # code = 0

classify_done:
    mv   a0, t0               # Return code in a0
```

Translate the following C leaf function—combining RV32M remainder, division, and multiplication from [RISC-V Instructions](/dynamic-courses/computer-architecture/03-riscv-instructions/08-riscv-instructions/) with an `if-else` inside a `do-while` loop—into complete RV32IM assembly:

```c
int collatz_bound(int n, int limit) {
    int steps = 0;

        if (n % 2 == 0) {

        }

}
```

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

Tracing `n = 5, limit = 4` confirms the bottom-tested loop behavior:
- **Pass 1:** `5 % 2 != 0` $\to$ `n = 3 * 5 + 1 = 16`, `steps = 1`; `16 > 4` holds (`bgt` repeats).
- **Pass 2:** `16 % 2 == 0` $\to$ `n = 16 / 2 = 8`, `steps = 2`; `8 > 4` holds (`bgt` repeats).
- **Pass 3:** `8 % 2 == 0` $\to$ `n = 8 / 2 = 4`, `steps = 3`; `4 > 4` is false (`bgt` falls through, returning `3`).

The complete RV32IM leaf implementation is:

```asm
# Arguments: a0 = int n, a1 = int limit
# Returns:   a0 = int steps
collatz_bound:
    li   t0, 0                # steps = 0
    li   t1, 2                # Constant 2
    li   t2, 3                # Constant 3

reduce_top:
    rem  t3, a0, t1           # t3 = n % 2
    bnez t3, odd_branch       # Inverted (n % 2 == 0): jump if remainder != 0

    div  a0, a0, t1           # then: n = n / 2
    j    step_count           # Mandatory jump over else!

odd_branch:
    mul  a0, a0, t2           # n = 3 * n
    addi a0, a0, 1            # n = 3 * n + 1

step_count:
    addi t0, t0, 1            # steps++
    bgt  a0, a1, reduce_top   # do-while (n > limit): non-inverted repeat branch!

    mv   a0, t0               # Return steps in a0
    ret
```

</details>

</Exercise>
