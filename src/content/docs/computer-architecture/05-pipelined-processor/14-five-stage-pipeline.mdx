## Pipelined Instruction Execution

In a single-cycle processor, every instruction must traverse instruction memory, the Register File, the ALU, data memory, and register write-back inside one long clock period $T_{\text{clk,single}}$. Even fast register-to-register instructions like `add` are forced to wait for the worst-case critical path of `lw`, depressing clock frequency $f_{\text{clk}} = 1 / T_{\text{clk}}$ in the [CPU Performance Equation](/dynamic-courses/computer-architecture/02-computer-performance/06-cpu-performance-equation/). **Instruction pipelining** splits that combinational path into five clocked stages separated by barrier registers so five consecutive instructions execute in staggered overlap—increasing **instruction throughput** rather than shrinking single-instruction latency.

<Divider label="1 · Example" />

### Five-Stage Timing Benchmark

Consider executing instructions from our shared sensor-calibration loop (`lw t0, 0(s0)` followed by `addi s0, s0, 4`) on a 32-bit RISC-V core whose hardware blocks have the combinational propagation delays measured below:

- **Instruction Fetch** (`IF`): $t_{\text{IF}} = 200\text{ ps}$
- **Instruction Decode** (`ID`): $t_{\text{ID}} = 120\text{ ps}$
- **Execute / Address** (`EX`): $t_{\text{EX}} = 180\text{ ps}$
- **Data Memory** (`MEM`): $t_{\text{MEM}} = 250\text{ ps}$
- **Write Back** (`WB`): $t_{\text{WB}} = 100\text{ ps}$

Inserting four clocked interstage pipeline registers (`IF/ID`, `ID/EX`, `EX/MEM`, `MEM/WB`) between these five blocks, as shown in [the figure](#fig-pipeline-datapath), adds flip-flop setup time $t_{\text{setup}} = 15\text{ ps}$ and clock-to-output propagation delay $t_{\text{cq}} = 15\text{ ps}$ per stage boundary.

On an **unpipelined single-cycle** datapath, `lw t0, 0(s0)` activates all five functional units sequentially within a single clock period (with no interstage barrier registers), fixing the minimum clock period at the sum of all five delays:

$$T_{\text{clk,single}} = 200 + 120 + 180 + 250 + 100 = 850\text{ ps}$$

On the **5-stage pipelined** datapath, all five stages are clocked by the same global oscillator, so the clock period must accommodate the single **slowest combinational stage** (`MEM` at $250\text{ ps}$) plus the interstage register overhead ($t_{\text{setup}} + t_{\text{cq}} = 30\text{ ps}$):

$$T_{\text{clk,pipe}} = \max(200, 120, 180, 250, 100) + 15 + 15 = 250 + 30 = 280\text{ ps}$$

Notice two immediate consequences of this timing split:

1. **Single-Instruction Latency Increases:** One isolated instruction now takes $5 \times 280\text{ ps} = 1400\text{ ps}$ from fetch to write-back—longer than the $850\text{ ps}$ single-cycle latency because faster stages (`WB` at $100\text{ ps}$, `ID` at $120\text{ ps}$) sit idle waiting for the $250\text{ ps}$ `MEM` bottleneck and pay $30\text{ ps}$ of latch overhead every cycle.
2. **Program Throughput Accelerates:** For a hazard-free stream of $\text{IC} = 1{,}000$ instructions, the first instruction completes on Cycle $5$ and the remaining $999$ instructions finish at a rate of one per cycle, taking $\text{IC} + 5 - 1 = 1{,}004$ cycles in total:

$$T_{\text{exec,single}} = 1{,}000 \times 850\text{ ps} = 850{,}000\text{ ps}, \qquad T_{\text{exec,pipe}} = 1{,}004 \times 280\text{ ps} = 281{,}120\text{ ps}$$

Dividing the two execution times yields an end-to-end speedup of $S = 850{,}000 / 281{,}120 = 3.02\times$ (approaching $850 / 280 = 3.04\times$ as $\text{IC} \to \infty$).

Below, we separate single-instruction latency from pipeline throughput, trace instruction execution and lockstep control through all five datapath stages, and derive the pipelined clock-period bound imposed by interstage register overhead.

### Throughput Versus Latency

To connect pipeline timing directly to the [CPU Performance Equation](/dynamic-courses/computer-architecture/02-computer-performance/06-cpu-performance-equation/), distinguish two metrics that students frequently conflate:

- **Instruction Latency:** Total elapsed time ($k \cdot T_{\text{clk,pipe}}$) for one instruction to traverse all $k$ pipeline stages from entry to completion.
- **Instruction Throughput:** Number of instructions retired per unit time ($\text{IC} / T_{\text{exec}}$).

In an unpipelined single-cycle processor ($\text{CPI}_{\text{single}} = 1$), the clock period must span the critical path across all $k$ phases:

$$T_{\text{clk,single}} = \sum_{i=1}^{k} t_{\text{stage},i}$$

When the datapath is partitioned into $k$ pipeline stages and executes $\text{IC}$ instructions without stalls ($\text{CPI}_{\text{ideal}} = 1$), filling the pipeline requires $k - 1$ initial cycles before the first instruction retires in stage `WB` on cycle $k$, followed by $\text{IC} - 1$ steady-state completion cycles:

$$N_{\text{cycles}} = k + (\text{IC} - 1) = \text{IC} + k - 1$$

Multiplying by $T_{\text{clk,pipe}}$ gives the exact pipelined execution time and speedup over the single-cycle baseline:

$$S = \frac{T_{\text{exec,single}}}{T_{\text{exec,pipe}}} = \frac{\text{IC} \cdot T_{\text{clk,single}}}{(\text{IC} + k - 1) \cdot T_{\text{clk,pipe}}} \;\xrightarrow{\;\text{IC} \gg k\;}\; \frac{T_{\text{clk,single}}}{T_{\text{clk,pipe}}}$$

Only in the idealized limit where all $k$ stages have identical delay ($t_{\text{stage},i} = \tau$) and interstage registers have zero delay ($t_{\text{setup}} + t_{\text{cq}} = 0$) does $T_{\text{clk,single}} / T_{\text{clk,pipe}}$ simplify to $(k\tau)/\tau = k$. Any **stage imbalance** or **register overhead** lowers the asymptotic speedup strictly below $k$.

### Stage Hardware Mechanics

The canonical RISC-V integer pipeline decomposes instruction execution into five ordered stages separated by four clocked registers (`IF/ID`, `ID/EX`, `EX/MEM`, `MEM/WB`):

$$\text{IF} \;\xrightarrow{\;\text{IF/ID}\;}\; \text{ID} \;\xrightarrow{\;\text{ID/EX}\;}\; \text{EX} \;\xrightarrow{\;\text{EX/MEM}\;}\; \text{MEM} \;\xrightarrow{\;\text{MEM/WB}\;}\; \text{WB}$$

1. **Stage `IF` (Instruction Fetch):** The 32-bit Program Counter (`PC`) indexes Instruction Memory to read the 32-bit machine instruction while a dedicated adder computes the sequential fall-through address $\text{PC} + 4$. On the rising clock edge, `IF/ID` latches `PC` and the 32-bit `Instruction` word.
2. **Stage `ID`** (Instruction Decode): Bit-fields of `Instruction` are sliced in parallel (`opcode = inst[6:0]`, `rd = inst[11:7]`, `funct3 = inst[14:12]`, `rs1 = inst[19:15]`, `rs2 = inst[24:20]`, `funct7 = inst[31:25]`). The dual-read-port Register File reads $\text{Data1} = \text{Reg}[rs1]$ and $\text{Data2} = \text{Reg}[rs2]$, the Immediate Generator sign-extends the 32-bit immediate `Imm`, and the combinational **Control Unit** decodes `opcode` to produce all downstream control signals at once. `ID/EX` latches `PC`, `Data1`, `Data2`, `Imm`, register indices (`rs1`, `rs2`, `rd`), and the `EX`, `MEM`, and `WB` control bundles.
3. **Stage `EX`** (Execute / Address): Controlled by `ALUSrc` and `ALUOp`, the main 32-bit ALU either computes register-register / register-immediate arithmetic (`add`, `sub`, `addi`, `and`, `or`) or adds base plus sign-extended offset ($\text{Data1} + \text{Imm}$) for `lw` and `sw`. In parallel, a dedicated branch adder computes $\text{PC} + \text{Imm}$ and the ALU evaluates branch comparison flags (`beq`, `bne`). `EX/MEM` latches `ALU_Result`, store payload `Data2`, branch target, comparison flag, destination index `rd`, and the remaining `MEM`/`WB` control signals.
4. **Stage `MEM` (Memory Access):** Using `ALU_Result` as the byte address, Data Memory reads a 32-bit word (`Read_Data`) when `MemRead = 1` (`lw`) or writes `Data2` into memory when `MemWrite = 1` (`sw`). Arithmetic instructions bypass the memory array untouched. `MEM/WB` latches `Read_Data`, `ALU_Result`, destination index `rd`, and the `WB` control bits (`RegWrite`, `MemtoReg`).
5. **Stage `WB` (Write Back):** Multiplexer `MemtoReg` selects between `Read_Data` (for `lw`) and `ALU_Result` (for R-type and I-type ALU instructions). When `RegWrite = 1`, the selected 32-bit value writes back into `Reg[rd]` (with writes to `x0` ignored in hardware).

### Lockstep Control Pipelining

Why are `MemRead`, `MemWrite`, `RegWrite`, and `MemtoReg` generated inside stage `ID` yet passed through `ID/EX`, `EX/MEM`, and `MEM/WB` instead of wired directly from the Control Unit to stages `MEM` and `WB`? Because five *different* instructions occupy the five stages during every clock cycle. If `ID` wired `RegWrite` directly to the Register File write-enable pin, decoding a `sw` (`RegWrite = 0`) in Cycle 4 would disable the write-back of an older `add` currently finishing stage `WB` in Cycle 4! Shifting each instruction's control bits alongside its data payload through the interstage registers guarantees that every control signal arrives at `EX`, `MEM`, and `WB` on the exact clock cycle its parent instruction reaches that stage.

### Clock Period Bound

Adding those four interstage barrier registers (`IF/ID`, `ID/EX`, `EX/MEM`, `MEM/WB`) to hold both data and control signals introduces a small flip-flop timing cost at every stage boundary. Because every interstage register consists of edge-triggered D flip-flops ([Flip-Flop Excitation Synthesis](/dynamic-courses/computer-architecture/01-synchronous-digital-systems/05-flip-flop-excitation-synthesis/)), data launched from one pipeline register after clock-to-Q delay $t_{\text{cq}}$ must propagate through the stage's combinational logic ($t_{\text{stage},i}$) and stabilize at least $t_{\text{setup}}$ before the next rising clock edge. Satisfying timing across all five stages simultaneously imposes the strict lower bound:

$$T_{\text{clk,pipe}} = \max_{i \in \{\text{IF},\text{ID},\text{EX},\text{MEM},\text{WB}\}}\!\left(t_{\text{stage},i}\right) + t_{\text{setup}} + t_{\text{cq}}$$

Even if an architect subdivided a $1000\text{ ps}$ datapath into $k = 50$ tiny stages of $20\text{ ps}$ each, a $30\text{ ps}$ flip-flop overhead ($t_{\text{setup}} + t_{\text{cq}}$) would clamp $T_{\text{clk,pipe}} \ge 50\text{ ps}$—meaning over $60\%$ of every clock cycle would be wasted latching flip-flops while hazard penalties explode.

<Callout type="bridge" title="Embedded Cores Versus Deep Superscalar Pipelines">

Low-power embedded microcontrollers such as ARM Cortex-M4 and bare-metal RISC-V RV32IM cores retain 3-to-5 stage in-order pipelines because short pipelines minimize flip-flop power overhead and keep interrupt and branch latencies small and deterministic. High-frequency desktop and server cores (AMD Zen, Intel Core, Apple M-series) stretch pipelines to $14\text{--}19$ stages to push $f_{\text{clk}}$ past $4\text{--}5\text{ GHz}$, pairing deep pipelining with wide superscalar issue ($4\text{--}8$ instructions/cycle) to achieve effective $\text{CPI} < 1$.

</Callout>

### Timing Calculation Procedure

1. **Single-Cycle Baseline:** Sum all stage combinational delays ($T_{\text{clk,single}} = \sum t_{\text{stage},i}$), omitting interstage pipeline register delays.
2. **Pipelined Clock Period:** Identify the single slowest stage $\max_i(t_{\text{stage},i})$ and add $t_{\text{setup}} + t_{\text{cq}}$ once: $T_{\text{clk,pipe}} = \max_i(t_{\text{stage},i}) + t_{\text{setup}} + t_{\text{cq}}$.
3. **Single-Instruction Latency:** Compare $1 \times T_{\text{clk,single}}$ against $k \times T_{\text{clk,pipe}}$ ($k = 5$).
4. **Execution Time and Speedup:** For $\text{IC}$ hazard-free instructions, compute $T_{\text{exec,pipe}} = (\text{IC} + k - 1) \cdot T_{\text{clk,pipe}}$ (or $\text{IC} \cdot \text{CPI}_{\text{pipe}} \cdot T_{\text{clk,pipe}}$ for large $\text{IC}$ with hazards) and form the ratio $S = T_{\text{exec,single}} / T_{\text{exec,pipe}}$.

<Callout type="warning" title="Common Mistakes">

1. **Dividing $T_{\text{clk,single}}$ by $5$:** Never compute $T_{\text{clk,pipe}}$ as $T_{\text{clk,single}} / 5$ when stage delays differ—always take $\max_i(t_{\text{stage},i}) + t_{\text{setup}} + t_{\text{cq}}$.
2. **Single-Cycle Register Overhead:** Unpipelined single-cycle datapaths do not contain `IF/ID`, `ID/EX`, `EX/MEM`, or `MEM/WB` barrier registers; only add $t_{\text{setup}} + t_{\text{cq}}$ (if given for pipeline latches) to $T_{\text{clk,pipe}}$.
3. **Mixing `EX` and `MEM`:** In RISC-V, `lw` and `sw` compute the effective byte address $\text{Reg}[rs1] + \text{Imm}$ during stage **`EX`**, and access Data Memory during stage **`MEM`**.

</Callout>

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

1. **Single-Cycle Clock Period:** Summing the five combinational delays across the `lw` critical path gives:
   $$T_{\text{clk,single}} = 250 + 150 + 200 + 300 + 100 = 1000\text{ ps} = 1.0\text{ ns}$$
2. **Pipelined Clock Period:** Stage `MEM` ($300\text{ ps}$) limits the clock period, plus $20 + 30 = 50\text{ ps}$ of interstage flip-flop overhead:
   $$T_{\text{clk,pipe}} = \max(250, 150, 200, 300, 100) + 20 + 30 = 300 + 50 = 350\text{ ps}$$
3. **Speedup** ($\text{IC} = 10{,}000$):
   $$T_{\text{exec,single}} = 10{,}000 \times 1000\text{ ps} = 10{,}000{,}000\text{ ps}$$
   $$T_{\text{exec,pipe}} = (10{,}000 + 5 - 1) \times 350\text{ ps} = 10{,}004 \times 350\text{ ps} = 3{,}501{,}400\text{ ps}$$
   $$S = \frac{10{,}000{,}000\text{ ps}}{3{,}501{,}400\text{ ps}} = 2.856\times$$
4. **Single-Instruction Latency:**
   - **Single-cycle:** $1 \times 1000\text{ ps} = 1000\text{ ps}$.
   - **5-stage pipeline:** $5 \times 350\text{ ps} = 1750\text{ ps}$ (latency increases by $75\%$ due to unbalanced stage padding and four register crossings, even as throughput speeds up by $2.86\times$).

</details>

   $$T_{\text{clk},6} = \max(200, 160, 240, 200, 200, 140) + 20 = 240 + 20 = 260\text{ ps} \implies f_{\text{clk},6} = \frac{1}{0.260\text{ ns}} = 3.846\text{ GHz}$$
3. **Net Execution-Time Speedup:** With dynamic instruction count $\text{IC}$ constant across both designs:
   $$S = \frac{T_{\text{exec},5}}{T_{\text{exec},6}} = \frac{\text{IC} \times \text{CPI}_5 \times T_{\text{clk},5}}{\text{IC} \times \text{CPI}_6 \times T_{\text{clk},6}} = \frac{1.15 \times 420\text{ ps}}{1.25 \times 260\text{ ps}} = \frac{483}{325} = 1.486\times$$
   Despite the $8.7\%$ rise in $\text{CPI}$, shrinking $T_{\text{clk}}$ from $420\text{ ps}$ to $260\text{ ps}$ delivers a **$48.6\%$ overall speedup**.

</details>
