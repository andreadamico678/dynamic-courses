## Address Bit Decomposition

In [Cache Block Placement](/dynamic-courses/computer-architecture/06-cache-memory/19-cache-block-placement/), mapping a byte address to a cache set required integer division ($j = \lfloor \text{Addr} / B \rfloor$) followed by a modulo operation ($j \bmod NS$). Because hardware designers choose both block size $B = 2^m$ and set count $NS = 2^n$ as exact powers of two, division and modulo require **zero arithmetic gates**: the cache simply slices the CPU's 32-bit byte address wires into three contiguous fields—**Tag ($t$ bits)**, **Index ($n$ bits)**, and **Byte Offset ($m$ bits)**.

<Divider label="1 · Example" />

### Decoding a Cache Address

Take our shared RV32IM data cache (`L1D`) with capacity $C = 16\text{ KiB} = 16{,}384\text{ bytes}$, block size $B = 64\text{ bytes}$, and **4-Way Set-Associative** organization ($N = 4$). Let us partition the 32-bit CPU address bus into Offset, Index, and Tag widths:

1. **Blocks and Sets:**
   $$NB = \frac{16{,}384}{64} = 256\text{ blocks}, \qquad NS = \frac{256}{4} = 64\text{ sets}$$
2. **Bit Field Widths** ($t + n + m = 32$):
   - **Byte Offset** ($m$): $m = \log_2(64) = 6\text{ bits} \implies \text{Addr}[5:0]$.
   - **Set Index** ($n$): $n = \log_2(64) = 6\text{ bits} \implies \text{Addr}[11:6]$.
   - **Tag** ($t$): $t = 32 - (6 + 6) = 20\text{ bits} \implies \text{Addr}[31:12]$.

[The address-decoding datapath](#fig-cache-address-decoding) shows how these three wire bundles drive the SRAM array: `Index` selects the row, `Tag` feeds the comparator gated with `Valid` to assert `Hit`, and `Block Offset` multiplexes the requested word out of the $B$-byte line.

We first derive the exact widths and bit-slice boundaries of the Offset, Index, and Tag fields from cache geometry, then examine how those widths trade off under the 32-bit conservation law as associativity changes.

### Field Width Derivation

In a byte-addressable 32-bit architecture such as RV32I ($2^{32}\text{ bytes} = 4\text{ GiB}$), every 32-bit byte address `Addr[31:0]` partitions into three non-overlapping bit slices from least significant to most significant (where any slice `[msb : lsb]` spans $\text{msb} - \text{lsb} + 1$ bits):

$$
\begin{array}{|c|c|c|}
\hline
\textbf{Tag } (t\text{ bits}) & \textbf{Index } (n\text{ bits}) & \textbf{Byte Offset } (m\text{ bits}) \\
\hline
\text{Addr}[31 : n+m] & \text{Addr}[n+m-1 : m] & \text{Addr}[m-1 : 0] \\
\hline
\end{array}
$$

1. **Byte/Word Offset** ($m$ bits): Because a block holds $B = 2^m$ contiguous bytes, selecting a specific byte inside that block requires:
   $$m = \log_2(B)$$
   For aligned 32-bit RISC-V words (`lw`, `sw`, and instructions), each word occupies $4$ bytes, so the Offset splits into a $2$-bit byte-within-word offset ($m_{\text{byte}} = \log_2 4 = 2$, `Addr[1:0] = 00`) and a word-within-block offset ($m_{\text{word}} = \log_2(B / 4) = m - 2$, `Addr[m-1:2]`), satisfying $m_{\text{word}} + m_{\text{byte}} = m$.
2. **Set Index** ($n$ bits): Shifting out the lowest $m$ offset bits leaves the block address $j = \lfloor \text{Addr} / 2^m \rfloor = \text{Addr}[31:m]$. Taking $j \bmod NS$ when $NS = 2^n$ simply extracts the lowest $n$ bits of $j$, requiring:
   $$n = \log_2(NS) = \log_2\!\left(\frac{NB}{N}\right) = \log_2\!\left(\frac{C}{B \cdot N}\right)$$
   In a **Fully Associative** cache ($N = NB \implies NS = 1$), $n = \log_2(1) = 0\text{ bits}$—the Index field vanishes completely.
3. **Tag Field** ($t$ bits): Because $2^t$ distinct main memory blocks share the same $n$-bit Set Index, the cache stores the remaining upper address bits alongside each data block to verify ownership:
   $$t = 32 - n - m$$

When decoding a hexadecimal address, expand it to 32 binary bits, extract the lowest $m$ bits for Offset and the next $n$ bits for Index, and regroup the remaining upper $t$ bits into 4-bit hex nibbles starting from bit $n+m$ upward to read the hexadecimal Tag. Two addresses belong to the **same cache block**—guaranteeing a spatial-locality hit once that block is loaded—if and only if their Tag and Index bits are identical and only their Offset bits differ.

### Conservation Law and Associativity Shift

For any fixed 32-bit address bus, the field widths obey the strict conservation identity:

$$t + n + m = 32\text{ bits}$$

Writing cache parameters as powers of two ($C = 2^c\text{ B}$, $B = 2^m\text{ B}$, $N = 2^k$) gives $NB = 2^{c-m}$, $NS = 2^{c-m-k}$, $n = c - m - k$, and $t = 32 - c + k$. Holding total capacity $C$ and block size $B$ constant while varying associativity $N$ yields two mechanical invariants:

- **Offset Invariance:** Because $m = \log_2(B)$ depends solely on physical block size, $m$ **never changes** across Direct-Mapped, $2$-Way, $4$-Way, or Fully Associative organizations.
- **Associativity Bit Shift:** Doubling associativity ($N \to 2N$) halves the number of sets ($NS \to NS / 2$), shrinking `Index` by $1\text{ bit}$ ($n \to n - 1$) and expanding `Tag` by $1\text{ bit}$ ($t \to t + 1$). More generally, moving from Direct-Mapped ($N = 1$) to $N$-Way shifts $\log_2(N)$ bits directly from `Index` into `Tag`.

<Callout type="bridge" title="DMA Scanline Alignment">

In embedded camera pipelines (e.g., $640 \times 480$ or $1024 \times 768$ grayscale/RGB frames), if the byte width of one image row equals $2^{n+m}$ (the cache's way size $C / N$), then vertically adjacent pixels `(row, col)` and `(row + 1, col)` have identical `Index` and `Offset` bits and differ only in `Tag`. A $3 \times 3$ convolution kernel reading three vertically stacked pixels simultaneously can exceed associativity in a single set; padding each image row stride by $+64\text{ bytes}$ ($+1$ cache block) increments `Index` by $+1$ per row and spreads the kernel across adjacent sets.

</Callout>

<Divider label="3 · Summary" />

| Quantity | Symbol | Exact Formula (32-Bit CPU) | Bit Slice / Notes |
| :--- | :---: | :--- | :--- |
| **Total Blocks** | $NB$ | $C / B$ | Constant across associativity $N$ |
| **Total Sets** | $NS$ | $NB / N = C / (B \cdot N)$ | $NS = 1$ for Fully Associative |
| **Offset Width** | $m$ | $\log_2(B)$ | $\text{Addr}[m-1 : 0]$ |
| **Index Width** | $n$ | $\log_2(NS)$ | $\text{Addr}[n+m-1 : m]$ ($0$ if $NS=1$) |
| **Tag Width** | $t$ | $32 - n - m$ | $\text{Addr}[31 : n+m]$ |

### Address Partitioning Procedure

1. **Convert Powers of Two:** If capacity $C$ is given in KiB, convert to bytes ($1\text{ KiB} = 1{,}024\text{ B}$, $32\text{ KiB} = 32{,}768\text{ B}$) and compute $NB = C / B$ and $NS = NB / N$.
2. **Compute Field Widths:** Evaluate $m = \log_2(B)$, then $n = \log_2(NS)$, then $t = 32 - (n + m)$.
3. **Verify Bit Boundaries:** Label $\text{Offset } [m-1:0]$, $\text{Index } [n+m-1:m]$, and $\text{Tag } [31:n+m]$, confirming $t + n + m = 32$.
4. **Sanity-Check Associativity Shifts:** Verify that each doubling of $N$ subtracts $1\text{ bit}$ from $n$ and adds $1\text{ bit}$ to $t$ while leaving $m$ unchanged.

<Callout type="warning" title="Common Mistakes">

1. **Forgetting the Offset Bits $m$:** Never compute $\text{Tag} = 32 - n$! You must subtract **both** Index ($n$) and Byte Offset ($m = \log_2 B$): $t = 32 - n - m$.
2. **Off-by-One Ranges:** With $m = 6$ and $n = 10$, Offset is `[5:0]` ($6$ bits), Index is `[15:6]` ($10$ bits), and Tag is `[31:16]` ($16$ bits)—never `[6:0]` or `[16:6]`.
3. **Mixing $NB$ and $NS$:** Always divide $NB$ by $N$ *first* before taking $\log_2(NS)$ for the Index width.

</Callout>

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

In all three organizations, the block size is $B = 64\text{ bytes}$, so the Byte Offset field is invariant:

$$m = \log_2(64) = 6\text{ bits} \quad \big(\text{Addr}[5:0]\big)$$

1. **Direct-Mapped ($N = 1$):**
   - $NS = 1{,}024 / 1 = 1{,}024 \implies n = \log_2(1{,}024) = 10\text{ bits}$ (`Addr[15:6]`).
   - $t = 32 - (10 + 6) = 16\text{ bits}$ (`Addr[31:16]`).
2. **2-Way Set-Associative ($N = 2$):**
   - $NS = 1{,}024 / 2 = 512 \implies n = \log_2(512) = 9\text{ bits}$ (`Addr[14:6]`).
   - $t = 32 - (9 + 6) = 17\text{ bits}$ (`Addr[31:15]`).
3. **4-Way Set-Associative ($N = 4$):**
   - $NS = 1{,}024 / 4 = 256 \implies n = \log_2(256) = 8\text{ bits}$ (`Addr[13:6]`).
   - $t = 32 - (8 + 6) = 18\text{ bits}$ (`Addr[31:14]`).

</details>
