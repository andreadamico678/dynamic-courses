## Block Placement Overview

To hide the $40\text{--}80\text{ ns}$ latency of off-chip DRAM, an SRAM cache exploits **temporal locality** by retaining recently referenced words and **spatial locality** by transferring contiguous $B$-byte chunks called **cache blocks** (or cache lines). Whenever the processor requests a missing main memory block $j$, the cache controller must determine which physical slot(s) inside the $NB$-block cache are permitted to hold block $j$.

<Divider label="1 · Example" />

### Mapping Block 450 Across Associativities

Consider our shared RV32IM data cache (`L1D`) with total data capacity $C = 16\text{ KiB} = 16{,}384\text{ bytes}$ and block size $B = 64\text{ bytes}$. Dividing capacity by block size yields $NB = 16{,}384 / 64 = 256\text{ blocks}$ (numbered $0$ through $255$). Suppose the CPU executes a load from byte address $28{,}812$, which belongs to main memory block:

$$j = \left\lfloor \frac{28{,}812}{64} \right\rfloor = 450 \quad (\text{spanning bytes } 28{,}800\text{ to }28{,}863)$$

Let us trace exactly where block $j = 450$ is allowed to reside under each placement policy:

1. **Direct-Mapped ($N = 1$):** Every cache block forms its own single-slot set ($NS = 256$). Block $450$ maps to one unique slot via modulo arithmetic:
   $$\text{Block Index} = 450 \bmod 256 = 450 - (1 \times 256) = 194$$
   Block $450$ can sit **only in Block 194**, verified by $1$ tag comparator.
2. **2-Way Set-Associative ($N = 2$):** Pairing slots into $2$-block sets yields $NS = 256 / 2 = 128\text{ sets}$ (numbered $0$ through $127$):
   $$\text{Set Index} = 450 \bmod 128 = 450 - (3 \times 128) = 450 - 384 = 66$$
   Block $450$ maps to **Set 66** and may occupy **Way 0 or 1**, checked in parallel by $2$ tag comparators.
3. **4-Way Set-Associative ($N = 4$):** Grouping $4$ blocks per set yields $NS = 256 / 4 = 64\text{ sets}$:
   $$\text{Set Index} = 450 \bmod 64 = 450 - (7 \times 64) = 450 - 448 = 2$$
   Block $450$ maps to **Set 2** and may occupy **any of its 4 ways** (Ways $0\text{--}3$), checked by $4$ parallel comparators.
4. **Fully Associative** ($N = 256$): All $256$ slots form a single set ($NS = 1$). Block $450$ may reside in **any cache slot**, requiring $256$ parallel tag comparators.

[The placement diagram](#fig-cache-placement-taxonomy) illustrates the same geometric progression on a compact $8$-block cache ($NB = 8$) for main memory block $j = 12$: Direct-Mapped pins it to Block $12 \bmod 8 = 4$; $2$-Way ($NS = 4$) allows either way of Set $12 \bmod 4 = 0$; Fully Associative opens all $8$ slots.

<Divider label="2 · Theory" />

We begin by defining cache block addressing from total capacity $C$ and block size $B$, then trace the placement spectrum from Direct-Mapped ($N = 1$) through $N$-Way Set-Associative to Fully Associative ($N = NB$), and finish with the replacement policies that choose a victim when a set is full.

### Locality and Block Addressing

Main memory is partitioned into fixed-size blocks of $B$ bytes (where $B = 2^m$, typically $16\text{--}128\text{ bytes}$). A cache of data capacity $C$ bytes holds:

$$NB = \frac{C}{B} \text{ cache blocks}$$

Any CPU byte address maps deterministically to main memory block number:

$$j = \left\lfloor \frac{\text{Byte Address}}{B} \right\rfloor$$

which spans contiguous byte addresses $[j \cdot B,\; (j + 1) \cdot B - 1]$. Fetching the entire $B$-byte block on a miss converts **spatial locality** (such as stepping sequentially through RISC-V instructions at `PC + 4` or scanning an integer array) into immediate cache hits on the remaining words of the block, while keeping recently used blocks in SRAM exploits **temporal locality**.

### Direct-Mapped Organization

In a **Direct-Mapped** cache ($N = 1$), every cache block constitutes a $1$-way set ($NS = NB$), requiring $n = \log_2(NB)$ index bits, and main memory block $j$ has **exactly one legal cache location**:

$$\text{Block Index} = j \bmod NB, \qquad n = \log_2(NB)\text{ bits}$$

Because only one slot can ever hold block $j$, the hardware reads a single tag and needs **only $1$ comparator** and **no way-selection multiplexer**—delivering the fastest possible hit time $t_{\text{hit}}$ and lowest dynamic power. Its vulnerability is **ping-pong thrashing**: if a loop alternates between two active blocks $j_1$ and $j_2$ whose indices collide ($j_1 \equiv j_2 \pmod{NB}$, i.e., $|j_1 - j_2|$ is an integer multiple of $NB$, such as $j_1 = 18$ and $j_2 = 82$ in a $64$-block cache where $18 \bmod 64 = 82 \bmod 64 = 18$), the two blocks evict each other on every iteration even when the other $63$ blocks sit completely idle.

### Set-Associative Organization

An **$N$-Way Set-Associative** cache partitions its $NB$ total blocks into $NS$ sets of $N$ parallel ways each, requiring $n = \log_2(NS)$ bits to address the target set:

$$NS = \frac{NB}{N}, \qquad \text{Set Index} = j \bmod NS = j \bmod \left(\frac{NB}{N}\right), \qquad n = \log_2(NS)\text{ bits}$$

Main memory block $j$ maps to a single deterministic set ($j \bmod NS$), but may be placed in **any of the $N$ ways** inside that set:

1. **Set-Collision Rule:** Two distinct memory blocks $j_1 \neq j_2$ map to the same set if and only if $|j_1 - j_2|$ is an integer multiple of $NS$. Up to $N$ distinct colliding active blocks coexist simultaneously without evicting one another; holding $k$ colliding blocks without thrashing therefore requires $N \ge k$ ways. Revisiting $j_1 = 18$ and $j_2 = 82$ in an $NB = 64$, $2$-way cache ($NS = 32$): both map to Set $18$ ($18 \bmod 32 = 82 \bmod 32 = 18$) and occupy Way $0$ and Way $1$ with zero conflict evictions.
2. **Hardware Cost:** Because the requested block could sit in any way of the indexed set, the cache must inspect all $N$ ways simultaneously using **$N$ tag comparators** and an **$N$-to-$1$ multiplexer** to route the matching data word, slightly increasing $t_{\text{hit}}$ compared to Direct-Mapped.

### Fully Associative Organization

Setting $N = NB$ collapses the cache into a **single set** ($NS = NB / NB = 1$):

$$NS = 1 \implies \text{no modulo index } (n = 0\text{ bits})$$

Main memory block $j$ can occupy **any cache slot**, eliminating set-collision misses completely. However, checking all $NB$ slots in one cycle demands **$NB$ parallel comparators** (content-addressable memory), whose silicon area, wiring capacitance, and power restrict full associativity to small structures such as $16\text{--}64\text{-entry}$ Translation Lookaside Buffers (TLBs). Notice that Direct-Mapped ($N = 1$) and Fully Associative ($N = NB$) are simply the two endpoints of the general $N$-way formula $NS = NB / N$.

### Block Replacement Policies

Whenever a cache miss targets a set whose $N$ ways are all valid and occupied, the controller must pick a **victim way** to overwrite:

1. **Least Recently Used** (LRU): Evicts the way in the target set that has gone unreferenced (neither read nor written) for the longest time. LRU directly tracks temporal locality and achieves the lowest miss rate among practical policies, at the cost of maintaining age state bits per set (exact LRU is straightforward for $N = 2$ with $1$ status bit per set and $N = 4$, and approximated via Pseudo-LRU for $N \ge 8$).
2. **First-In, First-Out** (FIFO): Evicts the way that was loaded into the set earliest, regardless of subsequent hits, using a simple modulo-$N$ counter per set.
3. **Random:** Picks a victim way uniformly via a hardware pseudorandom counter, requiring zero per-set state bits while approaching LRU miss rates for larger $N$.

In a **Direct-Mapped** cache ($N = 1$), each set holds only one slot—the incoming block unconditionally overwrites that slot, so **zero replacement hardware** exists.

<Callout type="bridge" title="Sensor Buffer Stride Padding">

In embedded vision and LiDAR pipelines, allocating multiple $16\text{ KiB}$ or $32\text{ KiB}$ sensor buffers at exact power-of-two byte offsets causes corresponding pixels `frameA[i]` and `frameB[i]` to differ by an exact multiple of $NS \times B$, mapping every pair to the identical cache set. Padding buffer allocations by one extra $64\text{-byte}$ cache line shifts $j_B$ by $+1$, distributing accesses cleanly across sets without hardware changes.

</Callout>

<Divider label="3 · Summary" />

| Characteristic | Direct-Mapped ($N = 1$) | $N$-Way Set-Associative | Fully Associative ($N = NB$) |
| :--- | :---: | :---: | :---: |
| **Total Sets ($NS$)** | $NB$ | $NB / N$ | $1$ |
| **Placement Rule** | $\text{Block} = j \bmod NB$ | $\text{Set} = j \bmod NS$ | Any of the $NB$ slots |
| **Index Width ($n$)** | $\log_2(NB)$ bits | $\log_2(NS)$ bits | $0$ bits |
| **Parallel Comparators** | $1$ | $N$ | $NB$ |
| **Hit Time ($t_{\text{hit}}$)** | Fastest (no way mux) | Slightly slower ($N$-way mux) | Slowest (wide associative fan-in) |
| **Conflict Misses** | Highest | Low (sharp drop from $N=1 \to 4$) | Zero |
| **Replacement Policy** | None needed ($1$ slot) | LRU, FIFO, or Random | LRU, FIFO, or Random |

### Placement Calculation Procedure

1. **Find Total Blocks:** If given capacity $C$ and block size $B$, compute $NB = C / B$.
2. **Find Total Sets:** Divide by associativity $N$ to obtain $NS = NB / N$ (with $N = 1 \implies NS = NB$, and Fully Associative $\implies NS = 1$).
3. **Convert Byte Address:** If given a raw byte address instead of $j$, compute main memory block address $j = \lfloor \text{Byte Address} / B \rfloor$.
4. **Apply Set Modulo:** Compute $\text{Set Index} = j \bmod NS = j - NS \cdot \lfloor j / NS \rfloor$. State both the target set index and the number of candidate ways ($N$).

<Callout type="warning" title="Common Mistakes">

1. **Using $NB$ Not $NS$:** In an $N$-way set-associative cache, always write $NS = NB / N$ *first* and take $j \bmod NS$. Taking $j \bmod NB$ computes a nonexistent set whenever $j \bmod NB \ge NS$.
2. **Byte vs. Block Address:** Read carefully whether the problem gives block address $j$ directly or a raw byte address that must first be integer-divided by $B$.
3. **Replacement in Direct-Mapped:** Never assign LRU or FIFO overhead to a Direct-Mapped cache; with $1$ slot per set, eviction is unconditional.

</Callout>

A cache memory contains $NB = 64$ total blocks. The processor requests main memory block address $j = 50$.

1. Determine the mapped block or set index if the cache is **Direct-Mapped**, **2-Way Set-Associative**, and **4-Way Set-Associative**.
2. State the width in bits of the set index $n = \log_2(NS)$ in each of the three configurations.
3. Where can block $j = 50$ be placed if the $64$-block cache is **Fully Associative**?

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

Given $NB = 64\text{ blocks}$ and main memory block $j = 50$:

1. **Mapped Block / Set Indices:**
   - **Direct-Mapped ($N = 1$):**
     $$NS = \frac{64}{1} = 64 \implies \text{Block Index} = 50 \bmod 64 = 50$$
     Placed uniquely in **Block 50**.
   - **2-Way Set-Associative ($N = 2$):**
     $$NS = \frac{64}{2} = 32 \implies \text{Set Index} = 50 \bmod 32 = 50 - 32 = 18$$
     Placed in **Set 18** (either Way $0$ or Way $1$).
   - **4-Way Set-Associative ($N = 4$):**
     $$NS = \frac{64}{4} = 16 \implies \text{Set Index} = 50 \bmod 16 = 50 - (3 \times 16) = 2$$
     Placed in **Set 2** (any of Ways $0, 1, 2, 3$).

2. **Index Widths** ($n = \log_2 NS$):
   - Direct-Mapped: $n = \log_2(64) = 6\text{ bits}$.
   - 2-Way: $n = \log_2(32) = 5\text{ bits}$.
   - 4-Way: $n = \log_2(16) = 4\text{ bits}$.

3. **Fully Associative** ($N = 64$):
   $$NS = \frac{64}{64} = 1\text{ set} \quad (n = 0\text{ index bits})$$
   Block $j = 50$ may be placed in **any 64-block slot** in the cache.

</details>

A processor uses a data cache of total capacity $C = 8\text{ KiB}$ ($8{,}192\text{ bytes}$) with $B = 64\text{-byte}$ blocks, giving $NB = 8{,}192 / 64 = 128\text{ blocks}$. The CPU requests main memory block $j = 245$.

1. Determine the block index for a **Direct-Mapped** organization.
2. Determine the set index for a **2-Way Set-Associative** organization.
3. Determine the set index for an **8-Way Set-Associative** organization.
4. State how many parallel tag comparators are required during a hit lookup in each of the three organizations.

<details className="dc-solution">
<summary>Reveal Worked Solution</summary>

With $NB = 8{,}192 / 64 = 128\text{ blocks}$ and $j = 245$:

1. **Direct-Mapped ($N = 1$):**
   $$NS = 128 \implies \text{Block Index} = 245 \bmod 128 = 245 - 128 = 117 \quad (\text{Block 117})$$
2. **2-Way Set-Associative ($N = 2$):**
   $$NS = \frac{128}{2} = 64 \implies \text{Set Index} = 245 \bmod 64 = 245 - (3 \times 64) = 245 - 192 = 53 \quad (\text{Set 53})$$
3. **8-Way Set-Associative ($N = 8$):**
   $$NS = \frac{128}{8} = 16 \implies \text{Set Index} = 245 \bmod 16 = 245 - (15 \times 16) = 245 - 240 = 5 \quad (\text{Set 5})$$
4. **Parallel Tag Comparators:**
   - Direct-Mapped: **$1$ comparator**.
   - 2-Way Set-Associative: **$2$ parallel comparators**.
   - 8-Way Set-Associative: **$8$ parallel comparators**.

</details>
